<objective>
Build and test the two pure transforms the backfill and the account seeding run on: Supabase export row -> CBooking/Contact payload (D-06..D-10, D-18, D-21) and booking rows -> Account candidates (D-14). No I/O, no network; every rule that later decides what lands in the CRM is pinned here by tests.

Purpose: the exclusion predicate, payment-method rule, currency conversion and Prague time handling are the places a silent mapping error would put wrong data on every Account; testing them in isolation makes the live backfill a formality.
Output: two pure modules + two test files.
</objective>

CBooking payload contract (plan 80-04 creates these fields with exactly these names, types and options; plan 80-09 writes them):

| payload key | EspoCRM type | options / limits | source |
|---|---|---|---|
| name | varchar (built-in) | | booking_reference |
| supabaseBookingId | varchar | maxLength 36 | id |
| leg | enum | LEG_VALUES = ['', 'outbound', 'return'] | leg (null -> '') |
| pickupAt | datetime | 'YYYY-MM-DD HH:mm:ss' UTC | pickupAtUtc(row) |
| pickup | varchar | maxLength 255 | origin_address |
| dropoff | varchar | maxLength 255 | destination_address |
| tripType | enum | TRIP_TYPE_VALUES = ['transfer', 'hourly', 'daily', 'round_trip'] | trip_type |
| vehicleClass | enum | VEHICLE_CLASS_VALUES = ['business', 'first_class', 'business_van'] | vehicle_class |
| status | enum | BOOKING_STATUS_VALUES = ['unpaid', 'pending', 'confirmed', 'completed', 'cancelled', 'assigned', 'en_route', 'on_location'] | status |
| amount + amountCurrency | currency | amountCurrency always 'EUR' | amountEur(row) |
| paymentMethod | enum | PAYMENT_METHOD_VALUES = ['Stripe', 'Invoice', 'Cash', 'Other'] | inferPaymentMethod(row) |
| passengerName | varchar | maxLength 150 | first + ' ' + last, trimmed |
| flightNumber | varchar | maxLength 20 | flight_number |
| driverName | varchar | maxLength 100 | driver_name |
| source | enum | BOOKING_SOURCE_VALUES = ['online', 'manual', 'gnet'] | booking_source (null -> 'online') |
| adminLink | url | | buildAdminLink(booking_reference) |

FIELD_MAX_LENGTH = { supabaseBookingId: 36, pickup: 255, dropoff: 255, passengerName: 150, flightNumber: 20, driverName: 100 }.
SYNCED_BOOKING_FIELDS = the payload keys above (used by the backfill diff). contactId/accountId are added by the backfill, not by rowToBooking.
Contact payload: { firstName, lastName, emailAddress, phoneNumber } — lastName falls back to firstName, then to the email local part (EspoCRM requires a last name).
Account types (D-02 stored values, plan 80-05): ACCOUNT_TYPE_VALUES = ['Hotel', 'Agency', 'Corporate', 'Embassy', 'Other'].
Candidate shape: { key, name, domain, companyNames: string[], bookerCount, bookingCount, totalEur, suggestedType, confirm: false, type: null } — no email addresses stored.
