<assumption_delta_decision>
Signal: pluralization ("also captured as Leads") — Lead identity now has two origins (form inquiry and booking) instead of one.
Primary noun: the typed site reference `cSupabaseRef` = `inquiry:<uuid>` | `booking:<outbound booking uuid>`.
Decision: promote — the source-qualified reference is the single idempotency key for every Lead variant; a bare booking id is not used as a Lead key anywhere. Phase 80's `CBooking.supabaseBookingId` stays the key of the Booking entity (different entity, unchanged). For round trips the noun is the order, represented by its outbound leg (D-19).
Invariant test: Task 1 adds the round-trip test "every draft's ref parses back to (kind, uuid)" for both variants.
</assumption_delta_decision>

Purpose: every Lead decision lives in one I/O-free module that the dispatcher (81-07/09/10) applies; the CRM config plans (81-03/06) create exactly the names fixed here.
