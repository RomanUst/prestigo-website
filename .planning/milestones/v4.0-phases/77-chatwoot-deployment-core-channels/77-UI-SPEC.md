# Phase 77 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** the site-side surface only — the floating `ChatLauncher` button and its
click-opened menu (Chat on site / WhatsApp / Telegram), on all 7 locales, RTL-correct in Arabic. The
Chatwoot widget's own chrome (pre-chat form, message thread, greeting bubble) is rendered by Chatwoot's
`sdk.js` inside its own iframe and is styled via `window.chatwootSettings`/the Chatwoot dashboard, not by
this repo's CSS — those settings are recorded here as the branding contract Chatwoot must be configured
with (D-08), not as component markup this repo owns.

| Property | Value |

library for it would fragment the design system rather than serve it. This is a reasonable-call decision
per the ui-phase auto-mode default (Rule: make the reasonable call, don't stop to ask when the codebase
evidence is this one-sided); the owner can redirect if a shadcn primitive is wanted later (e.g. for the

CTA/button classes) rather than as an importable inventory.

## Spacing Scale

Declared values (must be multiples of 4, all already present as Tailwind v4 defaults):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside a menu item |
| sm | 8px | Gap between stacked menu items |
| md | 16px | Menu panel internal padding; launcher-to-viewport-edge offset on mobile |
| lg | 24px | Launcher-to-viewport-edge offset on desktop; menu-to-launcher vertical gap |
| xl | 32px | (not used by this component — reserved for section-level layout, unaffected) |

Exceptions:
- **56px launcher diameter** (`h-14 w-14`, a multiple of 8) — a circular icon-only floating action button
  reads as too small at 44px on its own against a full viewport; 56px is the standard floating-launcher
  size (WhatsApp/Intercom/Chatwoot's own default facade) and still exceeds the WCAG 2.5.5 minimum with
  margin, matching the project's own `.btn-primary` 44px rule as a floor, not a ceiling.
- **44px minimum touch target on every individual menu item row**, even though the row's visual content
  (icon 20px + label) is shorter — matches the existing `.btn-primary`/`.btn-ghost` `min-height: 44px`
  convention verbatim.

### Visual anchor
The primary visual anchor of the open menu is the 600-weight gold "Chat on site" row (gold icon + `--copper-light` label); the closed-state anchor is the gold launcher icon.

### Z-index (new value — the launcher is a new layer, does not exist yet)
- **Launcher button + closed state:** `z-40` — above ordinary page content, below `Nav`'s `z-50` (so an
  open mobile nav drawer or dropdown always wins if they'd ever visually compete) and below
  `CookieBanner`'s `z-[400]` (so the consent modal's backdrop fully covers the launcher while consent is
  outstanding — no dead click-through under the backdrop).
- **Open menu (the 3-item popover):** `z-40` as well, same stacking context as the launcher — it never
  needs to exceed `CookieBanner`'s `z-[400]` because D-02 requires the launcher to do nothing third-party
  before a click, and the consent modal already fully blocks interaction underneath it when visible.

## Typography

New UI surface only (the Chatwoot widget's own internal chrome is out of this repo's typographic control
— see Widget Branding Settings below for what IS configurable there).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Menu item label | 13px | 400 | 1.3 |
| Menu item label — "Chat on site" (first/primary item) | 13px | 600 | 1.3 |
| Reply-time hint / status microcopy (e.g. "Live chat unavailable") | 12px | 400 | 1.4 |
| `sr-only` launcher `aria-label` | n/a (not visually rendered) | n/a | n/a |

- Two weights only: **400 regular** (default) and **600 semibold**, both already loaded via
  `next/font/google` Inter (`weight: ['300','400','500','600']` in `SiteChrome.tsx` — no new font weight
  request needed). 600 is reserved for exactly one use: visually distinguishing "Chat on site" as the
  recommended/primary option in the 3-item menu (D-01's stated order). WhatsApp and Telegram stay 400.
- No `letter-spacing`/uppercase treatment on menu items (diverges deliberately from `.label`'s 0.28em
  uppercase tracking) — at 13px in a compact popover, that tracking reduces legibility; use normal case,
  sentence-style labels ("Chat on site", not "CHAT ON SITE").
- Non-Latin tracking reset: not applicable here since no uppercase/tracked text is used in this
  component (sidesteps the `:lang(ar)`/`:lang(hi)` reset rule other components need).
- RTL script rendering (ar) and Devanagari/CJK (hi/zh) inherit the per-locale font stack already wired in
  `SiteChrome.tsx` (`localeFontClassName` — Noto Sans Arabic/Devanagari/SC) automatically; this component
  adds no new font-loading logic.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0F1D2C` (`--anthracite`) | Page background behind/around the launcher; unaffected by this phase |
| Secondary (30%) | `#17293B` (`--anthracite-mid`) fill, `#2B4056` (`--anthracite-light`) 1px border | Launcher button fill (closed state) and the open-menu panel surface — matches every existing card surface in the app |
| Accent (10%) | `#BFA06A` (`--copper`) for non-text fills/borders/icon strokes; `#D4BB86` (`--copper-light`) for any gold **text** | Reserved for: the launcher icon glyph itself, the launcher's 1px border (idle), the launcher's hover/focus ring, the "Chat on site" menu-item icon, the 600-weight "Chat on site" label color. Never used as a background fill (matches the codebase's established AA-contrast rule — `--copper` fails WCAG AA as text-on-navy, `--copper-light` is the text-safe variant; see `app/globals.css:106-109` for the same rule already documented for `.label`) |
| Destructive | not applicable | No destructive action exists in this phase's UI surface (the launcher/menu has no delete/remove/cancel affordance) |

Accent reserved for (explicit, closed list): launcher icon stroke, launcher idle border, launcher
hover/focus ring, "Chat on site" menu-item icon, "Chat on site" label text color (`--copper-light`
variant only). WhatsApp and Telegram menu items use **monochrome** icons (`--offwhite` stroke, not their
platform brand green/blue) — a deliberate discretion call to keep the accent gold as the single
"recommended path" signal rather than diluting it with two more brand colors, and to keep the menu
visually calm/premium rather than looking like a generic social-icon row.

## UI Considerations

Probe run 2026-09-28 (ui-consideration-probe, 4 elements: E1 launcher, E2 3-item menu, E3 "Chat on site" SDK load, E4 reply-time hint) — 24 applicable, all resolved (owner-confirmed) + keyboard/focus kind added by owner. Copy for loading/error lives in the Copywriting Contract; rows below reference it.

**Resolved — explicit (lift into `must_haves.truths`):**
- E1/E2 populated: the launcher renders identically on every public page in all 7 locales; opening it shows exactly 3 items in D-01 order (Chat on site → WhatsApp → Telegram).
- E3 loading: between the "Chat on site" click and `chatwootSDK.run()` completing, that item shows an inline loading state (spinner or `aria-busy="true"` + disabled); WhatsApp/Telegram items stay clickable.
- E3 error: if `sdk.js` fails to load (network/CSP/timeout), the menu shows `ChatLauncher.widgetError` inline and WhatsApp/Telegram items remain functional.
- E1 RTL: under `dir="rtl"` the launcher sits in the bottom-start (left) corner and the menu opens using logical properties only (no `left-`/`right-` classes); `chatwootSettings.position` is `'left'`.
- E1/E3 consent gate: before "Chat on site" is clicked, the page makes zero requests to the Chatwoot host and sets no Chatwoot cookie/localStorage key.
- Keyboard/focus: the launcher is a `<button>` with `aria-expanded` and `aria-controls`; Enter/Space toggles the menu; Esc closes it and returns focus to the launcher; a click/tap outside the menu closes it; menu items are reachable with Tab in D-01 order; a visible focus ring (`--copper`) shows on keyboard focus.

**Resolved — backstop (visual QA, held out):**
- { statement: "E2/E4 long-text: translated menu labels and the reply-time hint wrap (never truncate or overflow) in all 7 locales at 320px viewport width", verification: backstop }
- { statement: "E1/E2 overflow: the open menu stays fully inside the viewport at 320px width and does not cover the CookieBanner or Nav controls", verification: backstop }
- { statement: "E2 zero-one-many: the menu renders items from an array (not hardcoded to 3) so Phases 78/79 can add channels without layout breakage — checked at code review", verification: backstop }

**Dismissed (with reason):**
- empty (E1/E2/E3): no data-driven content — the menu is a fixed, static list; there is no zero-item state.
- partial (E2/E3): no records or fields to be partially present; SDK load is binary (loaded / error), covered by loading+error above.
- E1/E3 overflow/long-text beyond the rows above: the launcher is icon-only (no visible text); SDK load has no text of its own besides the error copy covered in long-text.
