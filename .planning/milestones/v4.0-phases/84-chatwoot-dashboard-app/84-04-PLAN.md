## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-84-14 | Information Disclosure | booking enumeration by arbitrary email/phone | high | mitigate | strict zod body with conversationId only (extra keys -> 400); lookup keys come only from verifyOperator's conversation response (D-03) |
| T-84-15 | Elevation of Privilege | admin session cookie used implicitly by the same-site iframe | high | mitigate | route never reads cookies; structural guard forbids cookie APIs and the cookie-session module; middleware strips the header (plan 84-05) |
| T-84-16 | Spoofing | brute-forcing Chatwoot tokens through our API (auth oracle) | medium | mitigate | fail-closed per-IP limiter (30/min), token shape check before any network call, 2000-byte body cap |
| T-84-17 | Information Disclosure | existence oracle between no_access and not_found | medium | mitigate | identical 403 body for both (route test) |
| T-84-18 | Tampering | panel path gaining a write (Supabase, Stripe, Chatwoot, EspoCRM) | high | mitigate | structural guard: RPC allowlist, no `.from(`, no write clients, GET-only Chatwoot client, iframe fetches only the panel API |
| T-84-19 | Information Disclosure | caching or referrer leakage of booking data | medium | mitigate | Cache-Control no-store and Referrer-Policy no-referrer on every response |
| T-84-20 | Information Disclosure | token/PII in logs | medium | mitigate | one `[panel] outcome= code=` line; log-spy test |
