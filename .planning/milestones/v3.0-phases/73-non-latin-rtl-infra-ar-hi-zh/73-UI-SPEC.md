# Phase 73 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase type note:** This is an infra/audit phase, not a new-surface design phase. No new components, no new copy authored by hand (translations are AI-pipeline output governed by `i18n/glossary.json`), no restyling. This contract exists to lock the **RTL/logical-property conversion rules**, **per-locale font-loading contract**, and the **non-regression bar** so the executor has zero visual-decision ambiguity when converting ~42 files.

Declared values (must be multiples of 4) — **unchanged by this phase**, sourced from the existing `app/globals.css` `@theme` block and Tailwind defaults already in use across the site:

| Token | Value | Usage |
|-------|-------|-------|

| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: **none.** This phase converts physical-direction Tailwind classes (`pl-*`/`pr-*`/`ml-*`/`mr-*`/`left-*`/`right-*`/`text-left`/`text-right`) to their **logical equivalents at the identical pixel value** (`ps-*`/`pe-*`/`ms-*`/`me-*`/`start-*`/`end-*`/`text-start`/`text-end`). The numeral suffix (spacing token) never changes — only the physical→logical axis name. A conversion that also changes a spacing value is out of scope and must be flagged, not silently "improved."

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (Tailwind default site-wide; unchanged) | 400 (Inter) | 1.5 (unchanged) for Latin/Cyrillic; **1.7–1.8 for `ar`/`hi` body text** (Arabic/Devanagari need more vertical breathing room — ligatures/matras render clipped at 1.5) |
| Label | 11px, 0.28em tracking (`.label` class, unchanged) | 400 | 1.4 |
| Heading | site h2/h3 sizes unchanged (Fraunces) | 400–500 | 1.25 (`--line-height-heading`, unchanged) for Latin/Cyrillic; **1.4 for `ar`/`hi` headings** |
| Display | site hero/display sizes unchanged (Fraunces, `--line-height-display: 1.1`) | 400 | 1.1 stays for Latin fallback text (brand wordmark, prices); **1.3 minimum wherever Noto Arabic/Devanagari/SC substitutes for the display face** — 1.1 clips Arabic ascenders/descenders and Devanagari matras |

**Font-size parity rule:** do not shrink or enlarge type when a non-Latin font substitutes for Fraunces/Inter at the same DOM node. Keep the existing `px`/`rem` value; only `line-height` and (per below) `letter-spacing` may differ per script.

**Letter-spacing rule — critical, do not skip:**
- `letter-spacing` (`tracking-*`, `.label`'s `0.28em`, `--letter-spacing-nav: 0.18em`, `--letter-spacing-wide: 0.12em`, `--letter-spacing-logo: 0.75em`) is a **Latin-script convention** and must be **suppressed (reset to `0` / `normal`) for Arabic and Devanagari text** — positive tracking breaks Arabic letter joining (the script is cursive/contextual-shaping) and visually fragments Devanagari conjuncts. Apply via a `:lang(ar)`/`:lang(hi)` CSS override (or a locale-conditional class on the same element) wherever these tracking utilities currently apply to translated copy — e.g. `.label`, nav items, section eyebrows.
- **Chinese (`zh`) keeps normal/tight tracking** (CJK does not use letter-spacing conventions the same way, but positive tracking does not break CJK glyphs the way it breaks Arabic joining) — no override needed for `zh`, default to `0` if any doubt, never widen.
- Latin brand tokens embedded inside non-Latin copy (see Color/Brand row below) keep their **original tracking value** even on `/ar/`/`/hi/`/`/zh/` pages — the override targets translated body/label text, not the DNT brand string spans.

**Fallback/tofu guard:** any DOM node rendering `ar`/`hi`/`zh` text must resolve through the locale's Noto font before falling to the Latin stack — a fallback glyph box ("tofu") anywhere on `/ar/`, `/hi/`, `/zh/` is a regression, not a cosmetic nit (FONT-01 gate).

## Font Loading Per Locale (FONT-01)

Locked mechanism (per CONTEXT.md D-04): loaders declared at module scope in/near `components/SiteChrome.tsx` (Next.js `next/font` requires static, module-level calls — cannot be called conditionally), **application** of the resulting `className`/CSS variable is conditional on the resolved locale.

| Locale | Font | next/font loader | Applies to |
|--------|------|-------------------|------------|
| `ar` | Noto Sans Arabic | `Noto_Sans_Arabic` from `next/font/google`, `subsets: ['arabic']` | `<body>` (or a locale-scoped wrapper) on `/ar/*` only |
| `hi` | Noto Sans Devanagari | `Noto_Sans_Devanagari` from `next/font/google`, `subsets: ['devanagari']` | `/hi/*` only |
| `zh` | Noto Sans SC | `Noto_Sans_SC` from `next/font/google`, `subsets: ['chinese-simplified']` (heaviest of the three — CJK glyph coverage) | `/zh/*` only |
| `en`/`ru`/`es`/`fr` | unchanged | Fraunces + Inter (existing) | all pages, no new font weight added |

Rules:
1. **Never ship the Noto SC subset (or any of the three) to a locale that doesn't need it** — this is a hard LCP/weight-budget constraint from D-04, not a style preference. Verify via a build-output/network check that `/en/`, `/ru/`, `/es/`, `/fr/` requests carry zero Noto font bytes.
2. Fraunces/Inter variables (`--font-cormorant`, `--font-montserrat`) stay declared exactly as today; the new Noto variable(s) are additive CSS custom properties (e.g. `--font-noto-arabic`, `--font-noto-devanagari`, `--font-noto-sc`), applied only inside the locale-scoped wrapper, never globally on `<html>`/`<body>` for all locales.
3. `font-display: swap` on every new loader (matches the existing Fraunces/Inter convention) — no invisible-text flash blocking render.
4. `weight` list per Noto loader: match what's actually used in the UI — normally `['400', '500', '600']` to cover body/label/heading roles without over-fetching every weight Google Fonts offers.
5. Body text on non-Latin locales falls to the locale Noto font by default via the CSS `font-family` fallback chain (see next section) — components must not hardcode `font-family: var(--font-montserrat)` inline in a way that bypasses the fallback chain for translated strings.

## Font-Family Fallback Stack (brand-token isolation, D-05)

Per-locale body/heading `font-family` stack — Noto first, Latin brand faces as the fallback tier (so a stray Latin character inside translated copy still renders acceptably, but the **intent** is Noto-first for translated text):

```
/* ar */  font-family: var(--font-noto-arabic), var(--font-montserrat), 'Helvetica Neue', sans-serif;
/* hi */  font-family: var(--font-noto-devanagari), var(--font-montserrat), 'Helvetica Neue', sans-serif;
/* zh */  font-family: var(--font-noto-sc), var(--font-montserrat), 'Helvetica Neue', sans-serif;
```

**Brand-token isolation rule (D-05) — these DOM nodes always render in the Latin brand face, regardless of page locale:**

| Token | Example | Font | Rationale |
|-------|---------|------|-----------|
| Wordmark | `PRESTIGO` | Fraunces/Inter (existing `.label`/logo classes, unchanged) | brand identity must look identical on every locale |
| Prices | `€185`, `€…` | Inter (`--font-montserrat`) | numerals + currency symbol; matches existing DNT price-placeholder handling |
| Vehicle class names | `E-Class`, `S-Class`, `V-Class`, `Mercedes-Benz` | Inter/Fraunces per existing usage | already a DNT term in `i18n/glossary.json` |
| Phone | `+420 725 986 855` | Inter | already a DNT term |
| Domain | `rideprestigo.com` | Inter | already a DNT term |

**Implementation note:** these tokens are already isolated as literal strings by the Phase 72 DNT pipeline (`i18n/glossary.json` → `doNotTranslate`), so they appear verbatim inside translated `ar`/`hi`/`zh` strings. Wrap them in a `<span>`/inline element carrying an explicit `font-family: var(--font-montserrat)` (or the Fraunces var for the wordmark) so they don't inherit the surrounding Noto stack — do this at the same call sites the existing rich-text tags (`price`, `highlight`, `strong` — see glossary `richTextTags`) already isolate, not as a new parsing pass.

## Direction & Logical-Property Conversion (RTL-01)

**Scope (D-01):** `app/[locale]/**` route files + shared components they render. `app/(internal)/**` (admin/driver) is explicitly **out of scope** — stays hard-coded `lang="en"`/LTR, untouched.

**Mechanism (D-02):** native Tailwind v4 logical utilities only — no `tailwindcss-rtl` or any other plugin.

| Physical class | Logical replacement | Notes |
|---|---|---|
| `text-left` | `text-start` | ~35 files affected (grep count as of 2026-09-17) |
| `text-right` | `text-end` | included in the 35 above |
| `left-{n}` | `start-{n}` | absolute/fixed positioning, ~4 files |
| `right-{n}` | `end-{n}` | included in the 4 above |
| `pl-{n}` | `ps-{n}` | |
| `pr-{n}` | `pe-{n}` | |
| `ml-{n}` | `ms-{n}` | |
| `mr-{n}` | `me-{n}` | |
| `border-l`/`border-l-{n}` | `border-s`/`border-s-{n}` | audit for presence; not yet counted |
| `border-r`/`border-r-{n}` | `border-e`/`border-e-{n}` | audit for presence |
| `rounded-l-*` | `rounded-s-*` | audit for presence |
| `rounded-r-*` | `rounded-e-*` | audit for presence |
| `space-x-*`, `flex-row-reverse` | n/a | **0 occurrences found in this codebase** (confirmed CONTEXT.md + re-verified) — no conversion needed, do not introduce these patterns during the fix either |

**Do NOT convert (these are correct as physical properties and must stay that way):**
- Any class governing a genuinely non-mirroring element (see Mirroring Rules below) — e.g. a `left-*`/`right-*` used purely for a decorative background blob position that has no reading-direction meaning.
- Numeral/price/phone bidi-isolated spans — these get `direction: ltr` + `unicode-bidi: isolate` (or the `dir="ltr"` attribute), not a logical Tailwind class swap. See "Mixed LTR-in-RTL" below.

**`<html dir>` wiring:** already complete — `app/[locale]/layout.tsx` sets `dir={rtlLocales.includes(locale) ? 'rtl' : 'ltr'}` and `i18n/locales.ts` exports `rtlLocales = ['ar']`. This phase's work is exclusively the Tailwind-class audit/conversion, not the attribute plumbing.

## Mirroring Rules (D-03)

| Element | Mirrors in RTL? | Rationale |
|---|---|---|
| Chevrons / arrows encoding "next"/continue (wizard step arrows, `Nav.tsx` dropdown chevron) | **Yes — flip horizontally** | Encodes reading-direction progression; an RTL reader expects "forward" to point left |
| Booking wizard step progress indicator (left-to-right fill) | **Yes** | Same progression semantic |
| Journey-timeline A→B iconography (`journey-01/02/03` imagery captions, any arrow between origin/destination) | **Yes** | Encodes route direction reading order |
| Route-map directional arrows/markers (if any encode a travel-direction arrow, not the map itself) | **Yes**, arrow glyphs only — the map/`RouteMap` component's actual geography (pins, polyline) must NOT be mirrored, only UI chrome arrows around it |
| PRESTIGO logo/wordmark | **No** | Brand mark, fixed orientation on every locale |
| Checkmarks (✓ feature lists, inclusions) | **No** | Non-directional semantic (done/included), universal glyph |
| WhatsApp glyph (`HeroWhatsApp.tsx`) | **No** | Third-party brand mark, must render exactly as WhatsApp's guidelines require |
| Social icons (any platform glyph) | **No** | Brand marks |
| Star ratings / review icons | **No** | Non-directional |
| lucide-react icons used for non-directional meaning (`UserRound`, `Car`, `ShieldCheck`, `Clock` in `FeatureStrip.tsx`) | **No** | Icons represent a concept, not a direction |

**Implementation note:** Tailwind's `rtl:` variant (already available in v4 core, no plugin needed) is the mechanism for the mirror/no-mirror split — apply `rtl:rotate-180` (or `rtl:-scale-x-100`) only to the "Yes" rows above, never globally to every `lucide-react` icon.

## Mixed LTR-in-RTL (D-11 QA checklist item)

Numerals and Latin brand tokens must render LTR even inside an RTL paragraph:

| Content | Requirement |
|---|---|
| Prices (`€185`) | Numerals stay LTR reading order; the `€` symbol position relative to the number must not reverse |
| Phone (`+420 725 986 855`) | Stays LTR, un-reversed |
| Flight numbers (e.g. `OK123`) | Stays LTR |
| Times (`14:30`) | Stays LTR, colon order preserved |
| Dates | Stays in the numeral order the locale expects, not mirrored digit-by-digit |
| Booking EntryBar + map | Must not visually break — layout mirrors (labels/icons swap sides per the RTL-01 logical-class conversion) but the address/date/time **values** inside stay bidi-isolated |

Mechanism: wrap these values in a `<bdi>` element or apply `dir="ltr"` + `unicode-bidi: isolate` at the same span boundaries the existing DNT/rich-text isolation already uses (glossary `pricePlaceholderPattern`, `phoneNumbers`). Do not rely on the browser's default Unicode bidi algorithm alone for compound strings (e.g. "flight OK123 at 14:30") — mixed number+Arabic-text runs can still visually reorder incorrectly without an explicit isolate.

## Non-Regression Contract (D-12)

- `en` root output, `ru`/`es`/`fr` subpath output: **byte-for-byte unchanged** by this phase's RTL-class conversion and font changes. Enforced by an automated byte-parity check (extends the existing golden-HTML snapshot pattern), normalizing `priceValidUntil` (today+365, from `lib/jsonld.ts`) exactly as the existing snapshot tests already do.
- Converting a physical class to its logical equivalent must render **identically in LTR** (`ps-4` on an LTR page renders exactly like the `pl-4` it replaced) — logical properties resolve to the same physical side under `dir="ltr"`. Any visual diff on `en`/`ru`/`es`/`fr` from a "conversion" is a bug in that conversion, not an accepted tradeoff.
- No Noto font bytes are requested on any locale page that doesn't need that specific Noto family — e.g. `/en/`, `/ru/`, `/es/`, `/fr/` request zero Noto bytes; `/ar/` requests only Noto Sans Arabic (not Devanagari/SC); `/hi/` requests only Noto Sans Devanagari; `/zh/` requests only Noto Sans SC (D-04 weight-budget rule, restated here as a hard gate).
