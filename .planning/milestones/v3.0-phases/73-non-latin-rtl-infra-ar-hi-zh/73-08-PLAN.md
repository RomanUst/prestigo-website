Close CR-02 (missing DNT price bidi-isolation) on the two pages the code review named — `app/[locale]/routes/prague-berlin/page.tsx` and `app/[locale]/services/city-rides/page.tsx` — which are the ones in the review set that actually render AI-translated Arabic content with interpolated prices. ## Decision (CR-02 approach — stated concretely, per gap-scope)
`lib/content-interpolate.ts`'s existing `interpolate()` returns a plain string and is ALSO consumed by `generateMetadata()` (title/description/ogTitle) where a React node would break the Metadata type — so `interpolate()` itself must NOT be changed to emit JSX. Instead:
- **Sentence-level fields** (a price token embedded in translated prose — e.g. `content.cta.headingItalic`, `content.hero.intro`, `content.priceCallout.vClassLine`/`firstClassLine`): render via the NEW `interpolateBidi()` helper, which wraps only each substituted token in `<bdi>`. One helper fixes every such call site.
- **Bare price-token renders** (the whole rendered value is just a price — e.g. `v.price`, `c.price`, and the literal `€{businessHourly}/hr`): wrap the rendered value directly in an inline `<bdi>`.
- **Metadata / non-rendered strings** keep the plain-string `interpolate()`.
</objective>
