<objective>
Externalize the authentication surface AND introduce the Server-Action locale-threading pattern (RESEARCH Pattern 3 / PATTERNS Pattern E) — the one genuinely new architecture in Phase 70. `app/[locale]/login/actions.ts` gains a leading `locale` parameter and returns error strings via `getTranslations({namespace:'Errors', locale})`; `app/[locale]/login/page.tsx` binds the validated route locale into each `useActionState` call via `.bind(null, locale)` and renders its four modes from `Auth.login`; `components/auth/OAuthButtons.tsx` renders from `Auth.oauth`; and a shared `Errors` namespace collapses the six byte-identical repeated error strings into reused keys.

Purpose: This pattern has no in-repo precedent (RESEARCH A4 flags it as unexercised). Proving it here — right after the booking tracer and before the account surface reuses it — de-risks the whole server-side error-localization story on the agent's best tokens. The `Errors` namespace created here is consumed again by `account/actions.ts` in plan 70-08.

Output: shared `Errors` namespace; `Auth.login` + `Auth.oauth`; locale-threaded `login/actions.ts`; externalized `login/page.tsx` + `OAuthButtons.tsx`; new `tests/login-actions.test.ts`.
</objective>
