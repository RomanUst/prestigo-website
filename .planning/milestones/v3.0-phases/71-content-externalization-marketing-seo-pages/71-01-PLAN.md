<objective>
Establish the locale-aware content model as a production-quality end-to-end tracer slice: build the shared loaders (`getRouteContent`, `getPageContent`), the `interpolate` helper, and the `RoutePage` chrome namespace, then convert ONE real route page (`prague-vienna`, the canonical 391-line skeleton all 30 route pages share) fully off its hardcoded literals — proving byte-for-byte English parity — before Wave 2 expands the pattern to the other 29 routes and all non-route pages.

Purpose: De-risk the single largest content restructure of the milestone by proving the loader + fallback + interpolation + JSON-LD-from-content architecture on the hardest real page first. If the architecture is wrong, we discover it after one committed page, not after forty.
Output: Two content loaders, one interpolation helper, the `RoutePage` message namespace, `content/routes/en/prague-vienna.json`, the converted page, and the Wave-0 test infrastructure every Wave 2 route plan reuses.
</objective>

<assumption_delta_decision>
Primary noun: page content, previously modeled as single-locale hardcoded JSX literals inside each `page.tsx`.
Decision: **promote** to a locale-aware `(slug|page, locale)`-keyed content model. English is one variant resolved by EN-fallback — it is NOT added alongside a still-primary single-locale structure. The literals are removed from the page and the JSON becomes the source of truth (consistent with D-01 and D-06).
Rationale: Phase 72's re-runnable AI translation pipeline requires machine-readable, diffable per-locale content; a promoted model is the only shape that supports idempotent re-translation without touching component code.
</assumption_delta_decision>
