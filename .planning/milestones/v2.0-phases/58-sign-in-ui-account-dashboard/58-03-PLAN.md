## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser session → Nav UI | Nav reflects auth state read client-side; it gates only UI affordances, not data access (real authz is server-side RLS + middleware). |
| sign-out action → redirect | Sign out must not become an open-redirect vector. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-58-07 | Spoofing | Nav signed-in affordance | accept | Nav UI state is cosmetic; it shows menu items but every protected route is enforced by middleware + RLS server-side. A spoofed client state cannot grant data access. |
| T-58-08 | Tampering (open redirect) | Sign out | mitigate | Sign out uses the existing `customerSignOut` server action which hardcodes `redirect('/')` with no caller-supplied destination (RESEARCH Security Domain) — no redirect param surface added. |
| T-58-09 | Information Disclosure | static-page rendering | mitigate | Nav reads auth only via client onAuthStateChange (D-09); no `cookies()`/server `createClient()` import, so marketing pages stay static and no auth roundtrip leaks into SSR. Pre-hydration guest flash is the accepted trade-off. |
| T-58-SC | Tampering | npm/pip/cargo installs | accept | No package installs — RESEARCH Package Legitimacy Audit confirms zero new packages. |
</threat_model>
