<assumption_delta_decision>
**Primary noun:** the per-assignment driver link.
**Decision:** `add-alongside` — the permanent trip-link token is added as a SECOND token type on
`driver_assignments`, coexisting with the existing single-use accept/decline token rather than
consolidating them.
**Rationale:** accept/decline is a one-shot response action (single-use, 48h expiry, consumed via
`token_used_at`); the trip link is a durable read surface (no expiry, valid until terminal
status/reassignment). Different lifecycles → intentionally separate columns (DTRIP-07 requires
accept/decline to keep working unchanged).
**Accepted debt:** a future consolidation would only be forced if a THIRD link type with an overlapping
lifecycle appears; until then two columns is correct, not duplication. (Advisory — recorded, not
blocking.)
</assumption_delta_decision>
