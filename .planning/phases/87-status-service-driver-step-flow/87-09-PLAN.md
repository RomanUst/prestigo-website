<objective>
Server side of the no-show request (D-15) and the operator's response (D-16): the driver can ask for a no-show only after the free waiting time, the request raises alerts without touching status or money, and only the operator confirms or dismisses it.

Tracer: driver POST `{ action: 'request_no_show' }` -> route -> `requestNoShowForDriver` (threshold from settings + airport rule + on_location log time) -> `set_no_show_request` RPC -> operator email + `alert.no_show` outbox row -> `{ ok, noShowRequestedAt }`; the admin GET then shows the open request. Then the admin confirm/dismiss route, then the settings API and the airport helper extraction.

Purpose: D-15/D-16 complete the on-site part of the driver flow; Phases 89 and 91 reuse the thresholds and the request timestamp.
Output: `lib/no-show.ts`, `lib/airport.ts`, admin no-show route, settings API fields, operator email, tests.
</objective>
