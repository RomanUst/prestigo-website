<objective>
Server half of 87-UAT gap 3 ("Tapping Help opens a chat whose messages reach Chatwoot"): a token-gated endpoint that turns a live trip link into a Chatwoot widget identity for that driver, plus the Chatwoot attribute definitions that show which booking the chat is about.

Decision recorded while planning (code reading, Claude's discretion): the public identity route `/api/chatwoot/identity` derives identity only from the Supabase session and accepts no parameter by design, and drivers have no session, so a separate route under the CSRF-protected `/api/driver/trip/[token]` prefix is used instead of widening the public one. The driver identity carries a name only (no email or phone): Chatwoot merges contacts that share an email, and a driver who is also a customer (the owner testing as a driver, for example) would otherwise merge into their customer contact.

Tracer: POST `/api/driver/trip/<token>/help` -> token lookup (`driver_assignments` + `bookings` + `drivers`) -> `isTripLinkValid` -> `buildDriverWidgetConfig` -> 200 with the identified config, with the rate-limit key and the isolation-guard allowlist entry in place so the full suite stays green. Then rejections, inbox selection and response hygiene, then the attribute definitions.

Output: route, identity builder, rate-limit key, guard allowlist entry, attribute definitions, tests. Security-relevant (token-gated endpoint minting an HMAC identity): commit with the `security:` prefix.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| driver browser -> POST /api/driver/trip/[token]/help | bearer trip token in the path, untrusted request |
| server -> browser | HMAC identity (hash only) and the public website token |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-87-56 | Spoofing | minting a driver chat identity without a live link | high | mitigate | UUID check before DB, live lookup, isTripLinkValid (driver match, not declined, not terminal), uniform 400, 10/min/IP rate limit, CSRF Origin check via the /api/driver/trip prefix (Tasks 1-2 tests) |
| T-87-57 | Information Disclosure | response leaking the token, passenger data, driver email/phone or the HMAC secret | high | mitigate | body built only from base URL, public website token, driver identifier and hash, display name and booking reference; serialized-body negative assertions and no-store header (Task 2) |
| T-87-58 | Spoofing | a driver identity colliding with a customer contact (Chatwoot contact merge) | medium | mitigate | identifier namespaced 'driver:<uuid>' (customers use the bare user uuid); no email or phone in the driver identity, so Chatwoot has no email to merge on |
| T-87-59 | Denial of Service | VPS dependency on a driver request path (Phase 76 D-19) | medium | mitigate | the route reads env and computes the HMAC locally, no network call; allowlisted with that reason and the isolation guard test runs in Task 1 |
| T-87-60 | Elevation of Privilege | unidentified driver chats bypassing the CRM guard | medium | mitigate | fail closed: missing base URL, website token or HMAC secret returns { enabled: false } and the page offers the call option |
| T-87-SC | Tampering | npm/pip/cargo installs | high | mitigate | no package installs (zod, next and Supabase are existing dependencies); any install attempt is out of scope and must stop for a blocking human checkpoint |
</threat_model>
