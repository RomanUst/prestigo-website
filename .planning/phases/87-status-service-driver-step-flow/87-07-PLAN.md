<objective>
Make every GNet status push happen exactly once per status, even when the driver retaps or a push is retried (D-04, DRV-05), and pin the D-22 decision that on_board and no_show send nothing.

Tracer: admin/driver transition of a gnet booking -> service (applied CAS) -> `pushGnetForTransition` -> conditional claim on `gnet_bookings` -> one GNet call; a second call for the same status claims nothing and sends nothing; a failed push is retried once on the next call.

Purpose: success criterion 4 (each driver step pushed exactly once, no duplicates on retap or retry). The CAS winner is already the only pusher per transition (87-03); this plan closes the retry/replay duplicate.
Output: claim-based `lib/gnet-push.ts`, `tests/gnet-push.test.ts`, adapted GNet tests.
</objective>

<interfaces>
lib/gnet-push.ts (signature from 87-01 unchanged)
- pushGnetForTransition({ bookingId, bookingSource, status, amountEur, logTag }): Promise<void>
  1. return when bookingSource !== 'gnet' or prestigoToGnetStatus(status) is null (X = mapped value)
  2. claim: update gnet_bookings { last_push_status: X, last_push_error: null, last_pushed_at: now } eq booking_id, or(`last_push_status.is.null,last_push_status.neq.${X},last_push_error.not.is.null`), select('id, gnet_res_no')
  3. zero rows claimed: select id by booking_id; none -> console.error(`${logTag} no gnet_bookings row for`, bookingId); a row -> return silently (already pushed)
  4. pushGnetStatus(gnet_res_no, X, Number(amountEur).toFixed(2)); on throw update { last_push_error: message } by id (last_push_status stays X) and log `${logTag} failed` with ids and the error message
- Plan 87-08 calls it on a driver replay of an already-applied step, so a failed push is retried and a successful one is not repeated.
- Delivery semantics (D-04): at-most-once per status. The claim commits before the GNet call, so a crash or after() timeout between step 2 and the end of step 4 leaves the row marked as pushed with no error and that status is never sent. Accepted: the reverse order (push, then record) duplicates on retry, which D-04 forbids; the window is a single outbound call; the booking's next status still reaches GNet. Not fixed in this plan; recorded in the SUMMARY and carried to 87-13.
</interfaces>
