<objective>
Deliver the Chatwoot operator message for a driver's no-show request (D-16 b) through the existing async outbox, never from a request path.

Tracer: an `alert.no_show:<bookingId>:r<epoch>` outbox row -> `/api/integrations/dispatch` -> `dispatchOutboxKey` -> `deliverNoShowAlert` -> Chatwoot private note in the passenger's conversation, proven end to end with the fake Chatwoot harness. Then the operations-conversation fallback, the stale-request skip, the isolation-guard allowlist and the outbox labels.

Purpose: the operator works in Chatwoot; the no-show request must reach them there, while the driver's tap stays a fast, Chatwoot-free request (Pitfall 8). Plan 87-09 enqueues the row from the driver request.
Output: `lib/noshow-alert.ts`, key builder/parser in `lib/outbox.ts`, dispatcher branch, guard allowlist entry, tests.
</objective>
