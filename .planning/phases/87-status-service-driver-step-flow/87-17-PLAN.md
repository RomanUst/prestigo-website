<objective>
Make the driver Help chat (87-UAT gap 3) safe for the CRM before it exists, and fix the shared contract the chat plans 87-18 and 87-19 build on.

Why this plan exists: every Website-widget conversation runs through the Phase 83 bridge (`hook.chat_intake`, `hook.chat_contact`, `hook.chat_resolve`) and becomes an EspoCRM Lead unless it is a customer, a known contact, filtered or labelled no-lead. A driver asking the office for help is not a sales lead; without this guard every driver chat would add a fake "Website chat" Lead (and Phase 85 lead statistics would count it). The guard keys on the HMAC-verified Chatwoot contact identifier, so it works whichever inbox the owner picks in 87-20.

Tracer: `lib/driver-help-contract.ts` (identifier helpers) + the `ensureIntake` guard -> a `hook.chat_intake` row for a conversation whose contact identifier is `driver:<uuid>` ends `skipped / filtered_driver` with nothing written to EspoCRM. Then the contact and resolve paths and the rest of the contract (paths, storage, config validator) that 87-18 and 87-19 consume.

Output: contract module, two handler guards, tests.
</objective>

lib/driver-help-contract.ts (new; pure TypeScript, client-safe; browser globals only inside function bodies):
  export const DRIVER_CHAT_IDENTIFIER_PREFIX = 'driver:'
  export function driverChatIdentifier(driverId: string): string        // 'driver:' + lower-case uuid; throws on a non-uuid
  export function isDriverChatIdentifier(value: unknown): boolean         // exact 'driver:' + uuid v1-v8 shape, case-sensitive prefix
  export const DRIVER_HELP_PAGE_PATH = '/driver/trip/help'
  export function driverHelpConfigPath(tripToken: string): string        // '/api/driver/trip/' + encodeURIComponent(token) + '/help'
  export const DRIVER_HELP_STORAGE_KEY = 'prestigo_driver_help'
  export const DRIVER_HELP_CONTEXT_KEYS = ['chat_role', 'driver_trip_ref'] as const
  export type DriverHelpContext = { chat_role: 'driver'; driver_trip_ref: string }
  export type DriverHelpEnabledConfig = { enabled: true; baseUrl: string; websiteToken: string; user: WidgetIdentity; conversation: DriverHelpContext }
  export type DriverHelpConfigResponse = { enabled: false } | DriverHelpEnabledConfig
  export function parseDriverHelpConfig(value: unknown): DriverHelpEnabledConfig | null
      // enabled === true; isSafeWidgetBaseUrl(baseUrl); websiteToken non-empty string <= 200 chars;
      // user.identifier passes isDriverChatIdentifier; user.identifierHash /^[0-9a-f]{64}$/;
      // user.name string 1..120; user.email === null; user.phone === null;
      // conversation.chat_role === 'driver'; conversation.driver_trip_ref 1..60 chars, no control characters;
      // no other keys required, unknown keys ignored (the result is rebuilt from the checked fields only)
  export function saveDriverHelpConfig(value: unknown): boolean            // parse, then sessionStorage.setItem(KEY, JSON); false on invalid input or a storage error
  export function loadDriverHelpConfig(): DriverHelpEnabledConfig | null   // sessionStorage.getItem(KEY) -> JSON.parse -> parseDriverHelpConfig; null on any error
  export function openDriverHelpPage(): void                               // window.location.assign(DRIVER_HELP_PAGE_PATH): a hard navigation, never the Next router
</interfaces>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-87-53 | Information Disclosure | driver personal data copied into the CRM (Lead / Contact) | medium | mitigate | intake, contact and resolve paths skip driver identifiers before any CRM write (Tasks 1-2 tests with zero-write fakes) |
| T-87-54 | Spoofing | a visitor setting a driver: identifier to avoid Lead creation | low | accept | setUser identifiers require a valid HMAC on the inbox (Website inbox hmac_mandatory: true; 87-20 requires the same on a Drivers inbox); the only effect of a forged identifier is a missing CRM Lead for that visitor |
