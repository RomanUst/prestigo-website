# Phase 87 — UI Design Contract

> Visual and interaction contract for the rebuilt driver trip screen (`/driver/trip/[token]`) and the small admin additions that go with the new statuses (`on_board`, `no_show`), the "No-show requested" banner and the no-show waiting-time settings. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Locked inputs: `87-CONTEXT.md` D-01..D-22 (cited as D-nn) and the Phase 86 admin theme (`86-UI-SPEC.md`, reused, not reinvented). All UI copy in this phase is English-only and hard-coded (D-20; `app/(internal)` is `lang="en"`), so nothing is added to `messages/*` and no locale translation is needed. The driver never sees an amount or a price anywhere on this screen (D-06), which also satisfies the no-hard-coded-€ rule.

## Theme Architecture (contract)

1. **Always light (D-19).** The trip screen renders inside the Phase 86 light theme: `<div className="admin-shell driver-shell" data-admin-theme="light">`. No cookie is read, no toggle exists, `color-scheme: light` comes from the existing `.admin-shell[data-admin-theme="light"]` rule, so a phone in system dark mode still shows the cream theme.
2. **Where it lives.** New server layout `app/(internal)/driver/trip/layout.tsx` (scoped to `trip` only, so `/driver/response` is not restyled, D-21) imports the existing `app/(internal)/admin/admin-theme.css` and `app/(internal)/driver/trip/driver-trip.css`, and renders the wrapper above. The existing `html:has(.admin-shell[data-admin-theme="light"])` rule gives the page and overscroll area the cream background.
3. **`driver-trip.css`** (new, selector-scoped to `.admin-shell.driver-shell`, contains **no colour values**): declares the driver type scale tokens `--driver-fs-label: 12px`, `--driver-fs-body: 16px`, `--driver-fs-heading: 20px`, `--driver-fs-display: 28px`; sets `.driver-shell { min-height: 100dvh }` (the base `.admin-shell` uses `100vh`, which is taller than the visible area in mobile browsers). Pull-to-refresh is left enabled (no `overscroll-behavior` override).
4. **Colour rule.** TSX under `app/(internal)/driver/trip/**` uses only `var(--admin-*)` and `var(--status-*)`. The current page's `#f87171`, `#4ade80` and dark `--anthracite`/`--copper` references are removed. See "Guard Test Contract".
5. **Map surface.** `RouteMap` keeps its cream greyscale style (already matches the light theme). Its internal marker/polyline hex literals live in `components/booking/` (outside the guarded paths) and are not changed. Google logo and attribution must remain visible: nothing may overlap the bottom 32px of the map area (see layout rule on the sheet).

## Screen and Component Contract

### Page states (server decides, `tripLinkViewState`)

| State | When | Renders |
|-------|------|---------|
| `active` | token valid, driver match, assignment not declined, booking status not terminal | `TripScreen` (below) |
| `completed` | booking status `completed` (D-17) | `TripCompleted`, details hidden |
| `ended` | `cancelled`, `no_show`, reassigned, declined, unknown or malformed token | `InvalidTripLinkView` (restyled, copy unchanged in meaning, one uniform view so reasons cannot be told apart) |

Anti-enumeration rule is preserved: unknown token and ended trips render the identical view. `cancelled` and `no_show` are treated as `ended`, not `completed` (resolves the D-09 / D-17 overlap, Claude's call per D-17).

### No-show block (D-15, D-16) — only while status is `on_location`

Rendered between the address timeline and the slide control; the slide control for "Passenger on board" stays in place at all times.

| Condition | Renders |
|-----------|---------|
| Before `noShowAvailableAt` (server-supplied ISO, computed as `max(pickup instant, arrival instant) + threshold`) | Caption only, Label 12/400 `--admin-text-muted`, with `Clock` 20px: "You can request a no-show after 14:35." |
| At or after `noShowAvailableAt`, no open request | Button "Request no-show": full width, 48px high, 1px `--admin-border-strong`, `--admin-text` text on transparent, Body 16/500, radius `--admin-radius-md` (neutral, not destructive: it changes no status and charges nothing). Tap opens `ConfirmStepDialog` in "no-show request" mode. |
| Open request (`noShowRequestedAt` set) | Info line instead of the button: `Clock` 20px + Body 16/400 `--status-info-fg` text "No-show requested at 14:41. The office is trying to reach the passenger." (`role="status"`). If the office dismisses ("Client found") the next refresh removes the line and the button returns (only if the threshold has passed). |

The client flips the caption to the button at `noShowAvailableAt` with a single `setTimeout` and re-checks on `visibilitychange`; the server remains the authority and rejects an early request (409 `too_early`).

### `SlideToAdvance` — interaction contract (D-12, D-13, D-14)

Dimensions: track height **64px**, full sheet content width, pill radius 32px (exception to the radius tokens), 1px `--admin-border-strong` border (control boundary, >= 3:1), background `--admin-hover`. Knob **56x56** circle, inset 4px, left-aligned at rest, `ChevronsRight` 24px. Centered label Body 16/500 `--admin-text`; secondary line (locked state only) Label 12/400 `--admin-text-muted`. Label never sits under the knob at rest (label area starts after the knob width, `padding-left: 64px`).

States:

| State | Knob | Track label | Behaviour |
|-------|------|-------------|-----------|
| `ready` | fill `--admin-accent`, icon `--admin-on-accent` | next step label (table below) | draggable |
| `dragging` | same, follows pointer | label fades with progress (opacity 1 to 0.4) | released before 85% of travel snaps back (150ms ease-out); at >= 85% on release it locks at the end and opens the confirm dialog |
| `locked-early` (start gate, D-14) | fill `--admin-border`, icon `Lock` 24px in `--admin-text-muted` | "Too early to start" + line 2 "Unlocks at 12:30" | not draggable, `aria-disabled="true"`, drag does nothing, tap shows no popup. Unlock time is formatted in Europe/Prague: same Prague day "Unlocks at 06:15", otherwise "Unlocks on Tue 4 Nov at 06:15". |
| `locked-waiting` (status `confirmed`/`pending`/`unpaid`) | as locked-early | "Waiting for the office" + line 2 "The office has not released this trip yet." | not draggable |
| `locked-offline` (`navigator.onLine === false`) | as locked-early, icon `WifiOff` | "No connection" + line 2 "Steps cannot be saved offline." | returns to `ready` on the `online` event |
| `awaiting-confirm` | at end of track, accent | "Confirm to continue" | dialog open; dismissing the dialog ("Not yet", Escape, scrim) resets the knob to the start |
| `submitting` | at end, icon replaced by `LoaderCircle` 24px (spin 1s linear; static icon under `prefers-reduced-motion`) | "Saving…" | `aria-busy="true"`, input ignored (no double submit; server is idempotent anyway) |
| `success` | resets to start | next step label (state re-rendered from server truth) | live region announces "Status updated: On my way." |

Mechanics: pointer events with `setPointerCapture`; knob `touch-action: none; user-select: none`; track `touch-action: pan-y`. **Fallbacks (accessibility):** (1) `role="button"` on the knob with `aria-label` "Next step: On my way. Double tap to confirm." and Enter/Space activates the same path (opens the confirm dialog) without sliding; (2) press-and-hold the knob for 600ms (hold ring fills around the knob) activates the same path, for users who cannot drag; (3) a plain tap or click without drag does nothing visual except a 2s hint in the secondary line: "Slide to continue" (Label 12/400). Under `prefers-reduced-motion: reduce` there is no snap-back animation and no spinner rotation; positions jump.

Focus: visible 2px `--admin-focus` ring with 2px offset on the knob (and on the Help, Navigate, Call, handle, textarea and dialog buttons). After the dialog closes, focus returns to the knob.

### `ConfirmStepDialog` (D-13)

Custom dialog (not the admin `Modal`, whose 32px padding and 480px floor suit desktop admin): `role="dialog"`, `aria-modal="true"`, `aria-labelledby` the title. Scrim `--admin-scrim`, z-index 100. Sheet anchored to the bottom on phones (`align-items: flex-end`, bottom safe-area padding) and centered at >= 600px; `--admin-surface`, 1px `--admin-border`, top radius `--admin-radius-lg` (all corners when centered), `--admin-shadow-sheet`, padding 24px, max-width 480px. Content: title Heading 20/500; body Body 16/400: "Are you sure you want to move to **On my way**?" (the step label in weight 500); for `completed` add a second body paragraph in `--admin-text-muted`: "You cannot undo this. If a step is wrong, the office can fix it." Buttons stacked, full width, gap 8px: primary (the confirm button from the step table) 48px high, `--admin-accent` fill, `--admin-on-accent` text, Body 16/500, radius `--admin-radius-md`; then secondary "Not yet" 48px, 1px `--admin-border-strong`, transparent, `--admin-text`.

Behaviour: initial focus on "Not yet" (safe default for an irreversible action); focus is trapped; Escape, scrim tap and "Not yet" all cancel and reset the knob; no request is sent until the primary button is pressed. While submitting both buttons are disabled, the primary shows `LoaderCircle` and "Saving…", the dialog cannot be dismissed. On a network or server error the dialog stays open, an inline `role="alert"` line in `--status-danger-fg` shows the error copy and the primary label becomes "Try again". On `409` (step conflict, too early, trip changed by the office) the dialog closes, the knob resets, and the banner below appears.

Other modes of the same component: **no-show request** (title "Request a no-show", body "The office will try to reach the passenger. Nothing is charged and the trip stays open.", primary "Send request", secondary "Not yet"); **help** **[Superseded by Amendment B: chat is now the primary action, the call option is the fallback.]** (`HelpDialog`: title "Need help?", body "Call the office if you cannot find the passenger, the trip details look wrong, or a step was tapped by mistake.", primary "Call the office" as a `tel:` link using `BUSINESS_TEL_URL` from `lib/contact-channels.ts`, with the number shown in Label 12 below it via `BUSINESS_PHONE_DISPLAY`; secondary "Close").

### Banners and live region

One banner slot directly above the slide control (inside the sticky area), single message at a time, Body 16/400, padding 8px 16px, radius `--admin-radius-md`, `--status-*-bg` fill with `--status-*-fg` text and a 20px leading icon, `role="status"` (info) or `role="alert"` (danger):

| Trigger | Family | Icon |
|---------|--------|------|
| 409 step conflict or trip changed by the office | info | `Info` |
| 409 too early (server rejected an early start) | amber | `Clock` |
| Network failure outside the dialog, 5xx | danger | `TriangleAlert` |
| 429 rate limit | amber | `Clock` |

A separate visually hidden `aria-live="polite"` region announces successful step changes and unlock events ("Start step unlocked."). Banners clear on the next successful action or after 8s for info.

### Freshness (no polling endpoint is added)

The client calls `router.refresh()` (server re-render, client state such as the expanded sheet and the note draft is preserved) on: any 409, `visibilitychange` to visible, the `online` event, and every 30s while the page is visible and the status is non-terminal. When a refresh turns the page into `ended` or `completed` the screen swaps without a message. A single `setTimeout` flips `locked-early` to `ready` at `unlocksAt`.

Exceptions:
- Touch targets are **48px minimum** on the driver screen (Help, Call, Navigate, handle, dialog buttons, note button, Request no-show), larger than the 44px admin floor because the driver uses one hand, often outdoors and sometimes while wearing gloves. Admin additions keep 44px.
- Slide control: track 64px (3xl), knob 56px, pill radius 32px, hold-to-activate ring 4px. Why: the knob is the 64px track minus a 4px inset on each side (64 - 2x4 = 56), so it never touches the border; the pill radius is half the track height; the 4px ring matches the knob inset so the hold progress reads as part of the control.
- Header height 56px. Why: a 48px touch target (Help) plus a 4px inset above and below, so the tap target is never cramped against the page edge.
- Handle bar 40x4px (radius 2px). Why: the conventional bottom-sheet grabber proportion; it is a decorative bar inside the 48px hit area, not a touch target, and 40px is wide enough to read as a handle at arm's length.
- Timeline dots 12px. Why: decorative markers, not touch targets; 12px is the smallest size that stays distinct from the 1px connecting line and reads next to 16px address text. They sit centred in a 16px column (an in-scale value), so no 12px spacing token exists.
- Completed icon 48px (2xl) in a 96px circle. Why: the circle is exactly twice the icon, which gives the glyph a 24px margin (lg) on every side.
- Map height `clamp(200px, 32dvh, 320px)`. Why: a fluid height lets the map, the collapsed sheet and the sticky 64px control fit together on a 360x640 phone (200px floor keeps the Google logo/attribution legible), while 320px caps it on tall screens so the sheet stays on first view.
- Bottom safe-area inset added to the sheet and dialog bottom padding.
- 1px borders and dividers; 2px focus outline with 2px offset.
- Z-index: sheet content 1 < sticky control 2 < dialog scrim and dialog 100 (nothing above the Phase 86 stack is needed on the driver route).

The widget is loaded there by a dynamic import after the driver's tap, identified as the driver (`driver:<uuid>`, hash and name only, never email or phone), with conversation attributes `{ chat_role: 'driver', driver_trip_ref: <booking reference> }`. No page URL, landing URL, referrer or UTM value is sent. The CSP allows the chat origin on that exact path only.
