<objective>
Establish `Booking.vehicleClasses.{business,firstClass,businessVan}.label` as the SINGLE source of truth for vehicle-class display labels, and externalize the four vehicle-facing files this plan owns: `types/booking.ts` (VEHICLE_CONFIG loses its translatable label), `components/booking/VehicleCard.tsx` (alt-text template), `components/booking/VehicleSlideshow.tsx` (local class-label map + prev/next aria + caption), `components/booking/StickyBookingPanel.tsx` (local label map + interpolated select aria), and `components/booking/steps/Step3Vehicle.tsx` (renders VEHICLE_CONFIG + date/time review). Mercedes model names stay literal (proper-noun rule).

Purpose: RESEARCH Pitfall 2 (and a repo-wide grep during planning) found the class-label triplet hand-duplicated across many in-scope files. This plan creates the one catalog entry and converts the vehicle-specific consumers; later plans (70-05 pricing/wizard, 70-06 Step6Payment, 70-08 account trips) reuse the SAME keys, and 70-08's phase gate greps for any residual hardcoded label across the whole in-scope tree.

Output: `Booking.vehicleClasses` (single source) + `Booking.vehicleCard` / `vehicleSlideshow` / `stickyPanel` / `step3vehicle`; four converted files; migrated tests.
</objective>
