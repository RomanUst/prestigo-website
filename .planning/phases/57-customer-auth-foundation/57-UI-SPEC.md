# Phase 57 — UI Design Contract

> Visual and interaction contract for the customer authentication foundation.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

Phase 57 introduces three new UI surfaces:

1. `/login` — customer sign-in / sign-up page (email magic-link, password, Google OAuth, Apple OAuth)
2. `/account` — minimal account landing that serves as the post-login redirect target and the authoritative sign-out surface for this phase
3. `/auth/callback` — invisible redirect route (no UI, server-only code exchange + `customer_profiles` upsert)

The full account-aware header nav (Sign in button, account dropdown) is **Phase 58 scope**. Phase 57 may add a minimal placeholder affordance in `components/Nav.tsx` only if needed to test sign-out; the definitive header treatment is out of scope here.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps |
| sm | 8px | Inline badge padding, wordmark spacing, label-to-input gap (exception below) |
| md | 16px | Input-to-input vertical gap, form field spacing |
| lg | 24px | Button-to-field gap, form section breaks |
| xl | 32px | Card internal padding (horizontal), page section breaks |
| 2xl | 48px | Card internal padding (vertical), full-page centering gaps |
| 3xl | 64px | — |

Exceptions:
- Label-to-input gap: **8px (sm)** — applies to customer `/login` form only; admin login retains its existing 6px inline style, which is out of scope for Phase 57.
- Touch targets: **44px min-height** on all interactive elements (CTA buttons, OAuth buttons, sign-out link) — WCAG 2.5.5 / Apple HIG, enforced by `.btn-primary` and `.btn-ghost` via `min-height: 44px`

## Typography

All typography mirrors established site patterns extracted from `app/globals.css` and the existing `app/admin/login/page.tsx` reference.

| Role | Font | Size | Weight | Line Height | Letter Spacing |
|------|------|------|--------|-------------|----------------|
| Display / page title | Cormorant Garamond | 28px | 400 | 1.1 (`--line-height-display`) | 0.12em |
| Section label / form label | Montserrat | 11px | 400 | 1.0 | 0.18em uppercase |
| Body / input value | Montserrat | 14px | 300 | 1.75 | 0.03em |
| Caption / helper text | Montserrat | 12px | 300 | 1.5 | 0.0em |

Exactly 4 sizes (28, 14, 12, 11px). Exactly 2 weights (400 regular, 300 light).

> **Note — 11px vs 12px distinction:** The 11px section/form labels are only 1px smaller than the 12px caption/helper text. To maintain visual hierarchy, 11px labels MUST use `text-transform: uppercase` and `letter-spacing: 0.18em` at all times. Do NOT render 11px labels in mixed-case without letter-spacing — they will be indistinguishable from 12px caption text.

| Text secondary | `#CFC9C2` (`--warmgrey`) | Form labels, nav items, placeholder intent text |

- Copper decorative line (`.copper-line`) if used on page
- Do NOT apply copper to: disabled states, secondary borders, or non-interactive decorative text

## Component Specs

### Auth Card (shared layout for `/login`)

```
max-width: 400px
width: 100%
padding: 48px 32px  (2xl vertical, xl horizontal)
background: var(--anthracite-mid)
border: 1px solid var(--anthracite-light)
border-radius: 8px
centered vertically + horizontally in 100vh anthracite background
```

This directly mirrors the existing `app/admin/login/page.tsx` card.

### Login Form — Tab Toggle (Magic-link / Password)

The sign-in form offers two modes switchable by the user:
- **Default mode:** Magic-link — single email field + "Send link" CTA
- **Secondary mode:** Password — email + password fields + "Sign in" CTA

Tab toggle: two text-only links/buttons above the form, 11px uppercase Montserrat, letter-spacing 0.18em. Active tab: `--offwhite`. Inactive tab: `--warmgrey`. No decorative underline on inactive; 1px solid `--copper` underline on active tab.

### Input Fields

```
width: 100%
padding: 12px 14px
background: var(--anthracite)
border: 1px solid var(--anthracite-light)
border-radius: 4px
color: var(--offwhite)
font-size: 14px (enforced globally by globals.css — prevents iOS zoom)
font-family: var(--font-montserrat)
```

Focus state: `outline: 2px solid var(--copper); outline-offset: 2px`
Error state: `border-color: #e74c3c`

### OAuth Buttons (Google, Apple)

```
width: 100%
padding: 12px 16px
background: transparent
border: 1px solid var(--anthracite-light)
border-radius: 4px
font-size: 11px, weight 400, letter-spacing 0.18em, uppercase
color: var(--warmgrey)
min-height: 44px
display: inline-flex; align-items: center; justify-content: center; gap: 8px
```

Hover state: `border-color: var(--copper); color: var(--offwhite)`
Active state: `transform: scale(0.97)`

Icon: Google — 18px SVG inline; Apple — 18px SVG inline. No icon library — use inline SVG.

### Divider between email and OAuth

Thin horizontal rule with centered "or" label:
```
border: none; border-top: 1px solid var(--anthracite-light)
"or" text: 11px Montserrat weight 400, --warmgrey, letter-spacing 0.18em uppercase
position: centered absolutely over the rule line
margin: 24px 0 (lg)
```

### Account Type Toggle (email registration only)

Radio-style button group, two options: "Personal" / "Corporate".
```
display: flex; gap: 8px
each option: padding 10px 20px, border 1px solid, border-radius 4px
unselected: border var(--anthracite-light), color var(--warmgrey), bg transparent
selected: border var(--copper), color var(--offwhite), bg transparent
font: 11px Montserrat weight 400, letter-spacing 0.18em, uppercase
min-height: 44px
```

Company name input (conditional, only visible when "Corporate" selected): same input style as above. Appears with a 0.3s ease fade-in animation.

### Minimal `/account` Page (Phase 57 only)

This is a skeleton — enough to verify gating and serve as sign-out surface. Phase 58 fills the full dashboard.

```
Layout: same full-page anthracite bg; max-w-7xl mx-auto px-6 md:px-12
Header: h1 "My Account" — Cormorant Garamond 28px weight 400, --offwhite
Subline: "You are signed in." — Montserrat 14px weight 300, --warmgrey
Sign out button: .btn-ghost class, label "Sign out", placed below the subline at mt-8 (32px)
```

No content sections, no trip history, no profile form — all Phase 58.

## Interaction States

| State | Visual Behaviour |
|-------|-----------------|
| Button loading / pending | `opacity: 0.7; cursor: wait` — matches admin login pattern |
| Button disabled | Same as loading; `pointer-events: none` |
| Input focus | 2px solid `--copper` outline, offset 2px |
| Input error | Border color `#e74c3c`; error message below input in 12px `#e74c3c` |
| Form success (magic-link sent) | Replace form content with confirmation message (copy below) |
| OAuth redirect in progress | No spinner needed — browser navigates away immediately |
| Reduced motion | All `animation-duration` collapsed to `0.01ms` via existing global rule |

## Accessibility

- All form inputs have associated `<label htmlFor>` — never `placeholder` as the only label
- Error messages are associated via `aria-describedby` on the input
- Auth card has `role="main"` landmark (single focus region on page)
- Loading state announced via `aria-busy="true"` on the submit button
- OAuth buttons have descriptive `aria-label` ("Sign in with Google", "Sign in with Apple")
- Tab order: wordmark → form fields top-to-bottom → primary CTA → secondary links → OAuth options
- `:focus-visible` at 2px `--copper` — enforced globally by `globals.css`
- All interactive elements minimum 44px touch target
