## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet -> /api/webhooks/chatwoot | anyone can POST; only an HMAC-valid request may reach the database |
| receiver -> webhook_ingest RPC | the only database entry of the inbound path; service role |
| outbox row -> QStash dispatcher | the row carries ids only; handlers re-read the source system |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-83-01 | Spoofing | forged Chatwoot webhook creating Leads/Contacts | high | mitigate | HMAC-SHA256 over `<ts>.<raw bytes>`, 401 before parsing, fail-closed without a secret, constant-time compare (route + webhook-verify tests) |
| T-83-02 | Tampering | replay of a captured signed request | high | mitigate | 300 s timestamp window both directions + (source, delivery id) primary key; replay -> duplicate, nothing enqueued |
| T-83-03 | Information Disclosure | timing side channel on the signature compare | medium | mitigate | `timingSafeEqual` after an explicit length check; unequal length returns bad_signature without throwing |
| T-83-04 | Denial of Service | oversized body / slow processing beyond Chatwoot's 5 s timeout | medium | mitigate | 1 MiB cap (header + byte check), one RPC per request, no CRM call (D-15) |
| T-83-05 | Elevation of Privilege | a valid signature enqueuing a non-hook event (erase.person, sync.*) | high | mitigate | event-type allowlist and key-prefix check inside webhook_ingest (RAISE), smoke step (c) |
| T-83-06 | Denial of Service | echo / feedback write storm on contact events | medium | mitigate | fingerprint echo drop in the receiver, loop fuse 20 / 10 min returning fused + ALERT (smoke step (d)) |
