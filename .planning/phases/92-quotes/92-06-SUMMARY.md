# Phase 92 Plan 06: Quote conversion Summary

`public.quote_convert_to_bookings` in migration 091 turns the accepted, paid version of a quote into one confirmed booking per line (booking, stops, ledger row, consent row) in one locked transaction, exactly once; the fake DB emulates it with the same reasons, and parity tests tie the SQL lists to TypeScript.

## What was built

- **Task 1 (tracer, `security:`)** - 091 section 9. Order of the function: lock the quote `FOR UPDATE`; paid (status `paid` or `paid_at` set) answers from the bookings already made when the intent equals `deposit_payment_intent_id`, else `intent_mismatch`; then `voided`, `cancelled`, `not_accepted`, `version_mismatch`, `intent_mismatch`, frozen version, the acceptance that owns the intent, `lines_mismatch` (p_lines positions equal the version's line positions, nothing else read except booking reference and hold instant), then a validation pass (`hold_at_missing`, missing amounts), then one insert per line in position order. Mode table: saved card with remainder -> `card_hold` / `card_saved` with remainder, currency, Stripe ids, `hold_at`; cash with remainder -> `cash_guarantee` / `card_saved` without `hold_at`; everything else -> `quote` / `none`. `bookings.payment_intent_id` and `pickup_utc` are not in the insert. Revoked from PUBLIC, anon, authenticated; granted to service_role.
- **Task 2** - fake DB rpc with the same order and reasons, the same mode table (`bookingModeFor`), the `bookings_quote_line_id_key` uniqueness, and a rollback of every touched table on a raise. `tests/quote-convert-fake.test.ts` (14 tests): tracer, exactly once, unique line id past the status check, W2 replay after a late cancel and after a void, every refusal writes nothing, lines / hold_at refusals, missing card ids raise, cash / payment_link / invoice, claim_due_payment_work picks only the card_hold booking, actor normalisation.
- **Task 3** - `vocabulary parity` block in `tests/migration-091.test.ts`: `quotes_status_check` = `QUOTE_STATUSES`, remainder method CHECK = `REMAINDER_METHODS`, `quote_events_kind_check` = `QUOTE_EVENT_KINDS`, every `v_mode` / `v_state` literal of the function is in `PAYMENT_MODES` and the bookings CHECK lists. Section 9 text tests (signature, SECURITY DEFINER, empty search_path, W2 order, validation before first write, p_lines keys, grants) live in the same file.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] Consent text limit widened**
- **Found during:** Task 1
- **Issue:** `booking_payment_consents.text_rendered` is limited to 2000 characters, `quote_acceptances.terms_rendered` to 4000. A longer acceptance text would raise on the consent insert and roll back a conversion whose money is already taken.
- **Fix:** 091 section 9 drops and re-adds `booking_payment_consents_text_rendered_check` as `char_length(text_rendered) <= 4000` (only the limit widens). Pinned by a text test; the fake test uses a text above 2000 characters.
- **Files modified:** supabase/migrations/091_quotes.sql, tests/migration-091.test.ts
- **Commit:** fbfbd7bd

### Plan choices worth knowing (not in the plan text)

- Consent row also carries `amount_minor` (the remainder) / `currency` / `planned_hold_at` for card_hold and cash_guarantee lines, `confirmed_at = now()` (the card is saved by the deposit itself) and the acceptance's `accepted_at`. The plan only listed text, hash, version, ip, user agent and locale. The extras gate reads `text_version` only.
- Missing amounts / shares on a frozen line (`deposit_share_minor`, `remainder_minor`, `amount_eur`, `amount_czk` NULL) answer `lines_mismatch` instead of raising; a missing acceptance for the intent, or an unfrozen version, answers `not_accepted`.
- A card-mode line with no customer / payment method (from the caller or the quote) RAISES `quote_card_ids_missing` (rolls back): such a booking would never be charged (Pitfall 3).
- Actor type outside admin / webhook / system is recorded as `system` (the ledger CHECK has no `client`); actor id is cut to 64 characters.
- Booking `client_phone` is `COALESCE(quote.client_phone, '')` (the erasure functions use `''`, so the column is treated as NOT NULL). `user_id` is not copied (not in the plan).
- A paid quote called with an unknown / null intent is `intent_mismatch`; a null intent before payment is also `intent_mismatch`.
