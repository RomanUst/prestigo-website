<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User click (locale selection) → navigation target | LocaleSwitcher resolves the target URL from a fixed `routing.locales` enum + `usePathname()`'s already-resolved internal path, then hands it to `@/i18n/routing`'s `router.replace` |
| New client component → existing per-request CSP nonce delivery | LocaleSwitcher is a new `'use client'` component added to Nav.tsx's render tree, which sits inside the CSP-nonced page shell |
| Client component → NEXT_LOCALE cookie | The switcher never writes the cookie directly; next-intl's own middleware sets it on the resulting navigation request |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-74-05-01 | Tampering | components/LocaleSwitcher.tsx navigation target | medium | mitigate | Target locale is drawn only from the fixed, typed `routing.locales`/`LOCALE_ENDONYMS` enumeration (never external input), and the path passed to `router.replace` is `usePathname()`'s already-resolved internal path — no raw string is ever accepted as a redirect target, eliminating an open-redirect surface and enforcing D-03's "never string concatenation" rule |
| T-74-05-02 | Tampering | NEXT_LOCALE cookie write | low | accept | LocaleSwitcher never calls `document.cookie` — the cookie is written exclusively by next-intl's own middleware on the resulting navigation (RESEARCH Pattern 5); the framework's locale-resolution guard also re-validates any cookie value against `routing.locales` server-side on every request |
| T-74-05-03 | Tampering | CSP nonce delivery in Nav.tsx | low | accept | LocaleSwitcher renders no `<script>` tag and no dynamically-injected markup; the project's CSP keeps `style-src 'unsafe-inline'` (the per-request nonce governs only `script-src`), so mounting a plain interactive dropdown introduces no new nonce-bearing surface |
| T-74-05-SC | Tampering | package installs | low | accept | No new packages — the component uses only next-intl/@/i18n/routing primitives already installed and audited (Phase 68) |
</threat_model>
