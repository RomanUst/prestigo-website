# Phase 74 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 74 is primarily non-visual SEO plumbing (`getAlternates()`, `generateMetadata`, sitemap, JSON-LD `inLanguage`) — those deliverables have no rendered UI and are out of this contract's scope. This UI-SPEC covers only the two genuinely new user-facing surfaces the phase introduces: the **LocaleSwitcher** (UX-01) and the **FirstVisitBanner** (UX-02). Both are new components (confirmed via repo grep during research — no existing `A ▾`-style switcher or banner exists to "replace"; see `74-RESEARCH.md` Pitfall 2).

## Spacing Scale

Declared values (must be multiples of 4), for any **new** spacing this phase introduces:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (trigger chevron, checkmark) |
| sm | 8px | Dropdown panel padding, gap between banner icon/text elements |
| md | 16px | Row padding (dropdown menu items, matches existing account-menu `12px 16px`), banner horizontal padding on mobile |
| lg | 24px | Banner horizontal padding on desktop, gap between banner message and button group |
| xl | 32px | (not used by new elements this phase — reserved) |
| 44px | 44px | WCAG 2.5.5 / Apple HIG touch-target minimum — trigger button `min-height`/`min-width`, every dropdown row `min-height` (pre-existing site-wide convention, not a 4× multiple but a fixed accessibility constant already used identically in `Nav.tsx`'s burger button and account-menu rows) |

**Exceptions:**
- `10px`/`14px`/`20px`/`24px`/`32px` non-4-multiple button paddings — the project's established `.btn-primary`/`.btn-ghost`/`.btn-secondary` classes and Nav's inline padding overrides (e.g. `{ padding: '10px 24px' }` on Book Now) use optical, non-grid values system-wide across all 73 prior phases. The FirstVisitBanner's "Switch to {locale}" / "Stay in {locale}" buttons **reuse these existing classes verbatim** (do not invent new padding) so they sit visually consistent with the Sign-in/Book-now buttons already in the same header row. This is a documented, pre-existing project convention, not a new exception introduced by this phase.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Switcher trigger label | 10px | 400 | 1 (single-line, uppercase, `letter-spacing: 0.18em` — matches Nav link convention) |
| Dropdown menu item (endonym) | 11px | 400 | 1 (matches account-menu row exactly: `12px 16px` padding, 44px min-height) — **sentence case, no `text-transform: uppercase`** (see Color/Copy notes below — uppercasing proper-noun language names, especially non-Latin ones, breaks brand voice and is meaningless for scripts with no case) |
| Banner message | 12px | 300 | 1.6 (conversational sentence, not an uppercase label — matches the project's `.body-text` light-weight reading convention, scaled down from its 14px baseline to fit a compact banner) |
| Banner buttons | 10px | 400 | 1 (uppercase, `letter-spacing: 0.15–0.35em`, matches `.btn-ghost`/`.btn-primary` exactly — reused classes, not new sizes) |

Only 2 weights used (matches the project's established 2-weight system): **300** (light — reading/body text) and **400** (regular — uppercase labels, buttons, menu items). No new weight is introduced.

Non-Latin letter-spacing: the existing `:lang(ar)`/`:lang(hi)` reset in `app/globals.css` (lines 129–140) automatically zeroes tracking on Arabic/Devanagari text — no new override needed for switcher/banner copy in those locales.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0F1D2C` (`--anthracite`) | Page/nav background — both new components sit on or float above this surface |
| Secondary (30%) | `#17293B` (`--anthracite-mid`) + `#2B4056` (`--anthracite-light`) | Dropdown panel + banner surface fill (`--anthracite-mid`); borders/dividers (`--anthracite-light`) |
| Accent (10%) | `#BFA06A` (`--copper`) / `#D4BB86` (`--copper-light`, AA-safe text variant) | See "Accent reserved for" below |
| Destructive | not applicable | No destructive actions in this phase's UI scope |

**Accent reserved for (explicit list — never "all interactive elements"):**
1. The currently-active locale's row in the LocaleSwitcher dropdown — text color `--copper-light` + a small inline checkmark icon (12px), the only visual indicator of "this is my current language."
2. The FirstVisitBanner's primary "Switch to {endonym}" button — border/hover-fill treatment matching `.btn-primary`'s existing copper border + copper-fill-on-hover, since this is the one suggested/emphasized action in the banner.
3. (Pre-existing, unchanged by this phase) Book Now button, "NEW" badge, focus-visible outlines — listed only to confirm the switcher/banner do not introduce a *competing* accent use elsewhere in the header.

Everything else in both components — trigger label, non-active dropdown rows, banner message text, banner secondary/dismiss button — uses `--warmgrey`/`--offwhite` only. Never copper as a fill/background for body text or inactive rows.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (LocaleSwitcher) | Not applicable — the switcher is a utility control (a menu of options), not a call-to-action. Each menu row's label is the target language's own endonym (`English`, `Русский`, `Español`, `Français`, `العربية`, `हिन्दी`, `中文`) — fixed structural strings, not translated (a language names itself the same way regardless of the page's current locale; lives in `i18n/locales.ts`, NOT `messages/*.json`, per the Phase 69 "structural config never moves into message JSON" convention). |
| Primary CTA (FirstVisitBanner) | **"Switch to {endonym}"** — e.g. "Switch to Русский" — the `{endonym}` is interpolated from the same structural label map as the switcher, the surrounding template string ("Switch to {locale}") is sourced from the catalog (`messages/<current-locale>.json`, namespace e.g. `Common.firstVisitBanner.switchTo`) so it renders in whatever locale the visitor is *currently* on, not the suggested one. |
| Banner suggestion message | **"This site is also available in {endonym}."** — catalog-sourced (current locale), `{endonym}` interpolated. Rendered above/alongside the two buttons, not as a question requiring the visitor to parse two languages at once (simpler and more consistent than mixing the current-locale chrome with a target-locale phrase, and reuses the existing `t.rich`/named-ICU interpolation pattern already used throughout Nav/CookieBanner). |
| Secondary/dismiss action (FirstVisitBanner) | **"Stay in {current endonym}"** — e.g. "Stay in English". Clicking this writes the `NEXT_LOCALE` cookie directly (Pattern 6's one legitimate hand-rolled-cookie case, since no locale-changing navigation occurs to trigger next-intl's automatic write) so the banner does not reappear on the next visit, and does **not** navigate or change the URL (D-05). |
| Empty state | Not applicable — neither component is data-driven. The switcher's 7-item list is a static structural array; the banner's visibility is a synchronous client-side computation (`navigator.language` vs current locale + cookie check), never a fetched/empty collection. |
| Error state | Not applicable — no network fetch exists in either component to fail. A locale-switch navigation failure (rare) falls through to Next.js's own standard error boundary, not a bespoke error UI. |
| Destructive confirmation | Not applicable — no destructive action exists in either component. |

## UI Considerations

Applicable state considerations resolved: **6 covered/backstop, 0 unresolved** (5 categories dismissed as not-applicable — see reasons below; both new elements are static/config-driven with no network fetch, so `empty`/`loading`/`error`/`partial` are structurally out of scope for this phase's UI, not gaps).

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| populated | LocaleSwitcher dropdown (list-collection) | ✅ covered | Dropdown always renders exactly 7 static locale rows (endonym label + current-locale checkmark), styled identically to Nav's existing account-menu rows (44px min-height, 11px/0.18em-tracking base, `--warmgrey`→`--offwhite` hover, `--copper-light` for the one active row) |
| overflow | LocaleSwitcher dropdown panel (nav) | 🧪 backstop | Dropdown panel `min-width: 200px` (wider than the account-menu's 160px) so the longest endonym string (`العربية` / `हिन्दी`) never wraps to a second line inside a menu row, in both LTR and RTL |
| long-text | LocaleSwitcher trigger (interactive-control) | ✅ covered | Trigger shows the fixed-width 2-letter locale code (`EN`/`RU`/`ES`/`FR`/`AR`/`HI`/`ZH`) + chevron — not the full endonym — so the header's control width never shifts when the active locale changes; the full endonym only appears inside dropdown rows |
| zero-one-many | LocaleSwitcher dropdown (list-collection) | ✅ covered | Exactly 7 rows always (compile-time structural array from `i18n/locales.ts`, never runtime-fetched) — no singular/plural copy variance applies |
| overflow | FirstVisitBanner message (static-content) | 🧪 backstop | Banner copy ("This site is also available in {endonym}." + two buttons) fits one row ≥360px viewport width; below that it wraps via `flex-wrap`/`flex-col` (never truncates or clips) |
| long-text | FirstVisitBanner buttons (interactive-control) | ✅ covered | "Switch to {endonym}" / "Stay in {endonym}" buttons use `flex-shrink-0` so labels never compress illegibly; the message text wraps independently in its own flex item |

**Dismissed (not applicable — no reason to raise):** `empty`/`loading`/`error`/`partial` for both components — neither the switcher's locale list nor the banner's suggestion computation involves a network fetch or async data source (switcher = static config array; banner = synchronous `navigator.language` read in a `useEffect`, per `74-RESEARCH.md` Pattern 6). A locale-switch navigation is standard client-side routing, not a bespoke fetch with its own loading/error UI.

**Open sequencing note for the planner (not a state-coverage gap, a z-order/mount-order constraint):** `CookieBanner` renders as a **blocking modal** (`fixed inset-0` backdrop + `overflow: hidden` body-scroll-lock) on first visit. `FirstVisitBanner` must **not** render simultaneously underneath/behind that backdrop — defer its visibility check until `getConsent()` (from `components/CookieBanner.tsx`) returns non-null (i.e., the cookie modal has been dismissed), so a first-time visitor never sees two overlapping prompts. `FirstVisitBanner`'s own `z-index` should sit below `CookieBanner`'s `z-[400]` (recommend `z-40` — non-blocking, no backdrop, does not need to win a stacking fight it should never be in if the mount-order guard is honored).

## Component Specifications

### LocaleSwitcher

- **Mount point:** `components/Nav.tsx`, inside the existing desktop `flex items-center gap-3` wrapper (the one that already holds the Sign-in/account-menu control + Book Now button) — inserted as the **first** item in that group (leftmost, per D-01's "near the Book button" placement intent), plus an equivalent entry in the mobile menu block (`#mobile-menu`).
- **Trigger:** a `<button>`, `'use client'`, `aria-haspopup="true"`, `aria-expanded`, `aria-controls`, showing the current locale's 2-letter code (uppercase) + the same chevron SVG path already used by the account-menu (`M2 4l4 4 4-4`, no RTL mirror needed — horizontally symmetric). `min-height`/`min-width: 44px` touch target. Font: 10px / weight 400 / `letter-spacing: 0.18em` / uppercase, color `--warmgrey` → `--offwhite` on hover, matching Nav's link-button convention (not `.btn-ghost`'s bordered treatment — this control is inline/borderless like a nav link, not boxed).
- **Panel:** `position: absolute; top: 100%; margin-top: 8px; inset-inline-end: 0` (mirrors the account-menu's proven positioning pattern exactly, including its automatic RTL correctness via the logical `inset-inline-end` property — do not use physical `right`/`left`). `min-width: 200px`, `background: var(--anthracite-mid)`, `border: 1px solid var(--anthracite-light)`, `border-radius: 4px`, `box-shadow: 0 8px 24px rgba(0,0,0,0.4)`, `padding: 8px`.
- **Rows:** each a `<Link href={pathname} locale={targetLocale}>` (from `@/i18n/routing`, **never** string concatenation — D-03), `role="menuitem"`, full-width, `padding: 12px 16px`, `min-height: 44px`, 11px / weight 400, **no `text-transform: uppercase`** (sentence case — see Typography note), color `--warmgrey` default → `--offwhite` on hover/focus, `--copper-light` + trailing checkmark icon for the currently-active locale's row only. Fixed display order: `en, ru, es, fr, ar, hi, zh` (matches ROADMAP/REQUIREMENTS locale order) — the list does **not** reorder itself to put the active locale first; only its row styling changes.
- **Behavior:** `router.replace(pathname, { locale: target })` (D-03: stays on the same page, never jumps to home) via `useRouter`/`usePathname` from `@/i18n/routing`. `NEXT_LOCALE` cookie is written automatically by next-intl's own middleware on the resulting navigation — no hand-rolled `document.cookie` write for this path (see `74-RESEARCH.md` Pattern 5). Target locale lacking a translation renders its EN-fallback content automatically (Phase 71 D-07) — the switcher does not need to know this in advance or show a different affordance for it.
- **RTL:** panel positioning already logical-property-safe (`inset-inline-end`); the chevron icon needs no mirror; dropdown row text-alignment inherits `dir="rtl"` automatically like every other block in the site.

### FirstVisitBanner

- **Mount point:** `components/SiteChrome.tsx`, alongside (after) `<CookieBanner />` — client component, `'use client'`, renders `null` until its own `useEffect` (client-only `navigator.language` read, **never** a server-side `headers()`/`cookies()` call — that would opt the entire route tree into dynamic rendering, per the load-bearing comment already in `SiteChrome.tsx`) decides to show itself, and only after `getConsent()` confirms the CookieBanner modal has been resolved (see sequencing note above).
- **Container:** `position: fixed; inset-inline: 0; bottom: 0; z-index: 40` (non-modal — no backdrop, no scroll-lock, unlike `CookieBanner`). `background: var(--anthracite-mid)`, `border-top: 1px solid var(--anthracite-light)`. Padding: `16px 24px` desktop, `16px` mobile. Layout: `flex items-center justify-between gap-4` desktop, collapsing to `flex-col gap-3` on narrow viewports (per the overflow consideration above).
- **Content:** message text (12px / weight 300 / `line-height: 1.6` / color `--offwhite` or `--warmgrey`) on the start side; a button group (`flex gap-3, flex-shrink-0`) on the end side containing the two actions described in the Copywriting Contract.
- **Buttons:** reuse `.btn-primary` (scaled down via the same inline-style-override pattern Nav already uses for Book Now, e.g. `padding: 10px 20px; font-size: 10px`) for "Switch to {endonym}", and a plain text-button style (no border, `--warmgrey` → `--offwhite` on hover, underline-on-hover) for "Stay in {current endonym}" — mirroring the visual weight difference between Nav's Book Now (primary) and Sign in (ghost/lower-weight) so the banner doesn't introduce a third, unfamiliar button treatment.
- **Behavior:** exactly two choices, no separate `×` dismiss icon (D-04's "two-choice prompt" — either explicit choice constitutes dismissal). "Switch" performs the same `router.replace(pathname, { locale })` navigation as the LocaleSwitcher (same-page, no home-jump). "Stay" writes `document.cookie = "NEXT_LOCALE=" + currentLocale + "; path=/; sameSite=lax; max-age=..."` directly (the one legitimate hand-rolled-cookie case, per Pattern 6/Pattern 5) so the banner is suppressed on return visits, with **zero URL change** either way (D-05 — no automatic redirect ever). Shown once per visitor (cookie-gated), never re-shown after either choice.
- **Crawler safety:** the server-rendered HTML is byte-identical regardless of `Accept-Language` (the component itself always renders, decision to show/hide happens client-side post-hydration) — no cloaking risk, matching D-04/D-05 exactly.
