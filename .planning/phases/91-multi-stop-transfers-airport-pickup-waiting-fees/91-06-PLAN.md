<objective>
The stops a client booked are saved with the booking in every checkout flow, kept in step with retries, and readable by every display surface through one loader.

Tracer: a card checkout (intent route) for a transfer with one stop waiting 45 minutes leaves one booking_stops row (position 1, wait 45, blocks 2, fee_per_block_eur 12, fee_eur 24) linked to the captured unpaid booking.

Purpose: STOP-04 persistence (Pitfalls 5 and 9). The admin (91-12), driver (91-13) and email/calendar (91-14) plans read stops through lib/booking-stops.ts.
Output: one server module, two capture call sites, two test files.
</objective>

- export async function loadStopsSafe(bookingId: string): Promise<BookingStop[]>   // [] on any error, console.error with the booking id only
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client-supplied attemptId to the stored booking | an attempt id must never let a client rewrite a confirmed booking |
| checkout to booking_stops (service role) | stop addresses are client PII |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-91-19 | Tampering | stops of a confirmed booking rewritten through a reused attemptId | high | mitigate | stops written only when captureUnpaidBooking affected an unpaid row; test with a confirmed attempt |
| T-91-20 | Repudiation | a paid booking whose stops were lost (driver never stops) | high | mitigate | pay-now fails closed with PaymentIntent cancel and 503 STOPS_NOT_SAVED; card and cash propagate the error before any Stripe object |
| T-91-21 | Information disclosure | stop addresses in logs | medium | mitigate | errors and logs carry booking ids and codes only; test on loadStopsSafe |
| T-91-SC | Tampering | npm/pip/cargo installs | high | accept | Rationale: this plan installs no package and runs no package-manager command, so there is no supply-chain surface to mitigate |
</threat_model>
