Analog for the public route: app/api/hourly-config/route.ts (public GET of a pricing setting for the wizard, never blocks the wizard). This route uses getPricingConfig, which already returns a safe fallback when the Supabase env is missing, and sets `export const dynamic = 'force-dynamic'` so nothing runs at build time (memory: no Supabase client during render/build). It returns no amounts: the wizard shows prices only from /api/calculate-price.

Supabase bulk upsert writes the union of keys of all rows, so the form must send waiting_rate_per_15min on every row (number or null); otherwise a row without the key could be written as NULL.

<interfaces>
GET /api/waiting-config -> 200 { freeMin: number, blockMin: number, maxMin: number, offeredClasses: VehicleClass[] }, header Cache-Control 'public, s-maxage=60, stale-while-revalidate=300'. Values from lib/stops.ts (STOP_FREE_WAIT_MIN, WAIT_BLOCK_MIN, MAX_STOP_WAIT_MIN) and Object.keys(getPricingConfig().waitingRate ?? {}) filtered to VEHICLE_CLASSES order. On any read error: same shape with offeredClasses [] (never 5xx).
PUT /api/admin/pricing: pricingConfigSchema gains waiting_rate_per_15min: z.number().positive().nullable().optional().
</interfaces>
