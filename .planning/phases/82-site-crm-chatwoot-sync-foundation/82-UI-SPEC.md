# Phase 82 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract.** Phase 82 has no customer-facing layout work. UI surfaces are:

1. Three new admin-only pages inside the existing Prestigo admin: `/admin/outbox`, `/admin/identities`, `/admin/erasure` (files under `app/(internal)/admin/(dashboard)/`).
2. One owner-facing email: the daily outbox-problems digest (D-11).
3. Public privacy policy **copy** (`content/pages/<locale>/privacy.json`, 7 locales). No new layout, no new components.

**Governing rule: do not invent a new visual language.** Every admin surface below is built from the existing admin vocabulary (inline styles driven by the `--anthracite*`, `--copper*`, `--offwhite`, `--warmgrey` CSS variables, `--font-cormorant` for headings, `--font-montserrat` for everything else, bordered 4px-radius cards, uppercase 11px wide-tracked labels, 48px table rows). Values quoted below were read from `app/(internal)/admin/(dashboard)/accounts/page.tsx`, `components/admin/{KPICard,StatusBadge,Modal,AccountForm,DriversTable,NotificationToggles,AdminSidebar}.tsx` and `app/globals.css` on 2026-10-18.

**Source legend.** `[CTX]` = locked by 82-CONTEXT.md, `[RES]` = from 82-RESEARCH.md, `[CODE]` = observed in the existing admin code, `[DEFAULT]` = researcher default (nothing upstream answered it; no user question was needed).

## Spacing Scale

Declared values (all multiples of 4); matches the existing admin (24px card padding, 16/32px gaps, 48px rows). `[CODE]`

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between a label and its input, badge vertical padding, icon-to-text gap inside buttons |
| sm | 8px | Badge/dot gap, compact button horizontal padding, gap between inline buttons ("Retry all" + "Don't retry") |
| md | 16px | Default element spacing, KPI row gap, form field gap, modal header margin |
| lg | 24px | Card padding, modal padding, h1 bottom margin when a button sits beside it, section gap |
| xl | 32px | Space between page sections (KPI row to banner to table), h1 bottom margin on pages without a toolbar, page side padding (layout already supplies it) |
| 2xl | 48px | Table row height (header row and body rows of every new table), empty-state vertical padding block |
| 3xl | 64px | Not used on these pages (mobile top offset is supplied by the layout) |

Table metrics for every NEW table (Outbox, Merged by phone, Shared numbers, Erasure log) are on-scale: cell horizontal padding 16px (md), header row height 48px (2xl), body row height 48px. The 12px cell padding and 40px header row seen in `accounts/page.tsx` apply only to that existing, unchanged Accounts page and must not be copied into Phase 82 code.

Exceptions (all inherited from existing components, not new): minimum touch target 44px × 44px for every button/link/checkbox row (already the admin rule); status dot 6px inside `StatusBadge`; `Modal` min-width 480px / max-width 560px (do not change; on viewports under 560px the modal scrolls horizontally — acceptable for an owner-only desktop tool).

Layout rules:
- Page wrapper: plain `<div>` inside the layout `<main>` (layout supplies 32px side padding and the `--anthracite-mid` background). Do not add a max-width container; tables are full width. Forms/cards that are not tables use `maxWidth: 720`.
- Header row: `display:flex; justify-content:space-between; align-items:center; margin: 0 0 24px` with the h1 on the left and the page's single primary action on the right (pattern of Accounts page).
- Tables sit in a bordered wrapper (`border: 1px solid var(--anthracite-light); border-radius: 4px`) with `overflow-x: auto` (not `hidden`) and the table `min-width: 720px`, so wide tables scroll on phones instead of clipping.

## Typography

Exactly four sizes and two weights. `[CODE]`: sizes 11/13/20/28 are the sizes the admin already uses; the 300 weight present in `Modal`, inputs and `KPICard` is inherited and must not be copied into new components.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (cells, paragraphs, inputs, buttons) | 13px | 400 | 1.5 |
| Label (uppercase column headers, KPI labels, badges, helper/error text, timestamps) | 11px | 400 | 1.5 |
| Heading (card titles, modal title, preview person heading) | 20px, `--font-cormorant` | 400 | 1.25 |
| Display (page h1) | 28px, `--font-cormorant`, letter-spacing 0.08em | 400 | 1.25 |

- Weight 500 is the only emphasis weight: row-primary link text and the person's email in the erasure preview. Nothing is bold (700) or light (300) in new code: new pages and components use weights 400 and 500 only (500 is the single emphasis weight; weight 300 is not used on any new page).
- Label style: `text-transform: uppercase; letter-spacing: 0.4em` for table headers and card captions (as `accounts/page.tsx`); badges use `0.08em` (as `StatusBadge`). Helper and error text under inputs is 11px, sentence case, no tracking.
- Inputs render at 16px because `globals.css` forces `input,select,textarea { font-size:16px !important }` (iOS zoom guard). That is expected; do not fight it.
- KPICard keeps its own internal 32px value size (inherited component, documented exception to the 4-size rule).
- Error codes and ids (e.g. `crm_unconfigured`, short booking ids) render as 13px body text in `var(--warmgrey)` — no monospace font is introduced.

## Color

Dark navy admin theme from `app/globals.css` (`--anthracite-*` names are legacy; values are navy). Do not hard-code the legacy neutral hexes (`#28282B`, `#36363B`, `#4E4E56`, `#B87333`) in new code except where a reused component or the copied `AccountForm` field styles already do. Light theme variables flip these automatically — use only the variables.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--anthracite-mid)` `#17293B` | Page background (set by layout) and card/table-body surfaces |
| Secondary (30%) | `var(--anthracite)` `#0F1D2C` for table header rows and inset panels; `var(--anthracite-light)` `#2B4056` for borders, dividers and row hover | Table `<thead>`, "what will be removed" panel, hover background, all 1px borders |
| Text | `var(--offwhite)` `#F3EEE3` primary, `var(--warmgrey)` `#A9AEB0` secondary | Body text / labels, helper text, error codes, timestamps |
| Accent (10%) | `var(--copper)` `#BFA06A` (`--copper-light` `#D4BB86` for text on dark) | See reserved list below |
| Destructive | `#f87171` text/border (existing admin red), `#2a1a1a` tinted background (existing `StatusBadge` cancelled bg) | Erasure only: destructive button, erasure warning panel, failed states |

Accent reserved for (and nothing else):
1. The single primary button of a view: "Retry all failed" (Outbox), "Mark number as shared" and "Split contact" (Identities), "Preview erasure" (Erasure). Filled `background: var(--copper); color: var(--anthracite)` (7:1 contrast; deliberately not the legacy `#B87333` + `#F5F2EE` pair, which is below AA on the new palette).
2. Row-primary links (e.g. the contact email that opens the account/bookings list) — `var(--copper)`, weight 500, as on the Accounts page.
3. The active tab indicator (2px bottom border) on the Identities page.
4. Keyboard focus ring: `outline: 2px solid var(--copper); outline-offset: 2px` on every new interactive element (`:focus-visible`).
5. KPICard hover border and label (inherited).

Secondary buttons (per-row "Retry event", dismiss buttons such as "Don't retry" and "Keep contact merged", and the refresh buttons) are outlined: transparent background, `1px solid var(--anthracite-light)`, text `var(--offwhite)`; hover border `var(--copper)`. Icon-only buttons use `var(--warmgrey)` that turns `var(--offwhite)` on hover.

Destructive is used for: the filled "Erase permanently" button (`background:#f87171; color: var(--anthracite)`), the erasure warning panel, the "Failed" state, and field error text. It is never used for "Split contact" (that is a gold primary: costly but not destructive of data) or for "Retry".

## Interaction & State Contract

**Focal point (one per page).** Outbox: the health banner, then the KPI row directly under it. Identities: the active tab's table (the tab strip is the only chrome above it). Erasure: the EMAIL OR PHONE search field first; once a preview exists, the preview heading (20px person email) takes over as the focal point.

**Dismissal.** No generic "Cancel" button exists anywhere in Phase 82. Every dismiss control is outcome-specific ("Don't retry", "Keep contact merged", "Don't mark number", "Discard preview", "Keep this person"); Esc and click-outside via `Modal` also close modals without any action.

**Data loading.** Each page fetches on mount (pattern of `accounts/page.tsx`), shows "Loading..." in the table cell, and a "Could not load ... Refresh to retry." message with a page-specific refresh button ("Refresh outbox" / "Refresh identities" / "Refresh erasure log") on non-OK responses. The Outbox page does not auto-poll (manual Refresh plus "Updated {time}"). The Erasure page polls its log every 10 s only while any row is Queued or In progress, and stops otherwise.

**Admin-only access.** Pages live under the `(dashboard)` layout, which already redirects non-admins; every API route follows the guard order 401 → 403 and the Origin-strict CSRF in middleware (`[RES]`). A 401/403 from a page fetch renders the load-error message.

**Tabs (Identities).** `role="tablist"` with two `role="tab"` buttons, `aria-selected`, `aria-controls`; Left/Right arrow keys move between tabs; active tab has a 2px `var(--copper)` bottom border and `var(--offwhite)` text, inactive tabs `var(--warmgrey)`. The tab buttons are 44px high. The selected tab is kept in the URL hash (`#shared`) so a reload and the "View Outbox" return link keep the place.

**Forms.** Inputs and labels use the copied `AccountForm` field styles; submit on Enter; the first field is focused on open; duplicate submits are blocked with a `submittingRef` (as `AccountForm`); while submitting, the primary button shows the "...ing" label and is disabled; errors render in `errorStyle` directly under the field they concern, form-level errors above the buttons.

**Modals.** Reuse `Modal` as is. Title text and buttons per the Copywriting Contract. Focus returns to the trigger on close (already built in). The erasure confirm modal closes on success and never closes automatically on failure.

**Keyboard & a11y.** Every table `<th>` has `scope="col"`; status badges carry text; icon-only buttons have `aria-label`; success/error messages use `aria-live="polite"` (errors in modals `role="alert"`); minimum 44px targets; focus ring per Color rule 4; color is never the only signal.

**Responsive.** Below 768px the admin shows its hamburger sidebar (existing). KPI cards wrap (`flex-wrap`, 16px gap, `minWidth: 200` inherited). Tables scroll horizontally inside their bordered wrapper. The header row wraps with the primary button under the h1 when narrower than the content (use `flex-wrap: wrap; gap: 16px`).

**Privacy of the screens.** The Outbox page and the digest email never display personal data. The Identities and Erasure-preview screens necessarily show emails and phones (admin-only, behind the layout guard). The Erasure log shows only a hash prefix, dates, counts and per-system status. After a request completes, no plain email for that person remains on any screen.
