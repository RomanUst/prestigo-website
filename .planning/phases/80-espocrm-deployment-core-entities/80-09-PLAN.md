Export SQL (RESEARCH Pattern 6 with the null-source fix; paginate with `order by b.created_at, b.id limit 150 offset {n}`):
select b.id, b.booking_reference, b.status, b.booking_source, b.leg, b.trip_type, b.vehicle_class, b.pickup_utc, b.pickup_date, b.pickup_time, b.origin_address, b.destination_address, b.amount_eur, b.amount_czk, b.client_first_name, b.client_last_name, b.client_email, b.client_phone, b.flight_number, b.payment_intent_id, b.payment_link_id, b.invoice_number, b.paid_at, b.attempt_id, b.user_id, b.created_at, d.name as driver_name, cp.company_name, cp.account_type
from public.bookings b left join public.drivers d on d.id = b.driver_id left join public.customer_profiles cp on cp.user_id = b.user_id
where not (b.status = 'unpaid' and coalesce(b.booking_source, 'online') = 'online' and b.payment_link_id is null)

Count SQL: select count(*) as total, count(*) filter (where b.status = 'unpaid' and coalesce(b.booking_source, 'online') = 'online' and b.payment_link_id is null) as abandoned from public.bookings b

Export files: infra/espocrm/.work/export/page-NN.json, each a JSON array of row objects (column names as above). loadExport accepts a single .json file or a directory of page-*.json files, de-duplicates rows by id (counted as duplicate_rows), and re-applies isAbandonedCheckout (counted as excluded_abandoned).

backfill.mjs CLI (identity apikey = prestigo-sync; exit 0 ok, 1 config, 2 API, 3 audit duplicates):
`node infra/espocrm/backfill.mjs [--dry-run] [--input path] [--limit N] [--delay-ms N] [--relink] [--audit]`
Default input infra/espocrm/.work/export/. Output lines (counts only):
- `export: rows=N eligible=N excluded_abandoned=N invalid=N duplicate_rows=N`
- `by_status: {value}=N ...`, `by_source: {value}=N ...`, `by_payment_method: Stripe=N Invoice=N Cash=N Other=N`
- `contacts: create=N update=N unchanged=N`
- `bookings: create=N update=N unchanged=N without_contact=N`
- `relink: update=N unchanged=N` (with --relink), `audit: records=N duplicates=N` (with --audit)
Preload (GET, maxSize 200, paged by offset, orderBy createdAt asc): Contact select id,emailAddress,accountId,phoneNumber; CBooking select id plus SYNCED_BOOKING_FIELDS plus contactId,accountId.
Diff: CBooking update when any synced field, contactId or accountId differs (null and '' are equal; numbers compared numerically). Contact: create when missing (POST, on 409 look up by emailAddress equals); update only phoneNumber when the existing one is empty.
Rows with --limit are taken in export order (created_at, id) after exclusion.
