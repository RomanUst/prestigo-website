- `createEspoClient({ config, fetchImpl?, timeoutMs? })` -> `{ identity, request(method, apiPath, body?) }`; apiPath is relative to `/api/v1` (e.g. `/Settings`); JSON in/out; returns parsed JSON or null for empty bodies

Header contract (verify against the 10.0.8 source before the first live call — see Task 2):
- apikey: `X-Api-Key: {key}`
- admin: first call `GET /api/v1/App/user` with `Espo-Authorization: base64(user:password)`; response carries `token`; every later call sends `Espo-Authorization: base64(user:token)` plus `Espo-Authorization-By-Token: true`

infra/espocrm/sync.mjs contract:
- `RESOURCE_ORDER` (this plan: ['settings']; later plans insert entities, links, fields, enums, layouts, roles, mail in that order)
- handler signature `async function syncX(ctx) -> { create, update, unchanged, skipped, removed }`; `ctx = { client, dryRun, log, configDir, readConfig(file), get(path), mutate(method, path, body) }` where `mutate` logs `[create]/[update]/[remove] {resource} {key}` and no-ops in dry run
- output line per resource: `{resource}: create=N update=N unchanged=N skipped=N removed=N`, then `summary: create=N update=N removed=N`
- exit codes: 0 ok, 1 config error (EspoConfigError), 2 API error (EspoApiError or anything else)
- CLI: `node infra/espocrm/sync.mjs [--dry-run] [--only a,b]`
