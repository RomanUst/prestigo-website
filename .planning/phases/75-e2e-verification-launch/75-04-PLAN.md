<objective>
Give every GA4 and Meta client-side event a `site_locale` dimension (D-10, D-12): one pathname-derived locale helper feeding `gtag('set', …)` (persistent across all GA4 events), the Pixel `trackMetaEvent` wrapper and the confirmation page's CAPI call — with the `/api/meta-capi` strict schema extended so the value actually reaches Meta — plus a production network-capture QA script.

Purpose: VER-01 requires "GA4/Meta analytics carry a locale dimension"; today no event carries one, and planning-time discovery found the CAPI strict schema was silently discarding the confirmation page's whole custom_data (content_type/content_ids are not allow-listed), so adding site_locale on the client alone would never reach Meta.
Output: locale helpers, GA4 + Meta wiring, schema fix with payload-level tests, `analytics_locale_audit.py` with a pre-deploy baseline.
</objective>

<assumption_delta_decision>
Noun flagged by the detector: **"custom" (GA4 custom dimension / Meta custom_data)** and **"fallback" (EN fallback for unknown locales)**.
Decision: **no-change**. Rationale: `site_locale` is one additional scalar attached to existing events and `'en'` is the existing root-locale default; no identity or data model moves from singular to plural — the event, user and booking models are unchanged.
</assumption_delta_decision>
