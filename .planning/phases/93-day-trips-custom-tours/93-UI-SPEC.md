# Phase 93 — UI Design Contract

> Visual and interaction contract for Day Trips & Custom Tours. Nine surfaces: (1) the tour page `/{locale}/services/<slug>-day-trip`, (2) the catalogue cards on `/{locale}/services/day-trips-from-prague` and the "You might also like" row, (3) the booking box and the mobile sticky bar, (4) the tour checkout `/{locale}/book/tour`, (5) the tour confirmation, (6) the custom-tour request page `/{locale}/book/custom-tour`, (7) admin tours (list, settings, editor), (8) admin custom-tour requests with "Create quote", (9) the tour rows in existing booking views, emails and alerts. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Locked inputs.** `93-CONTEXT.md` D-01..D-26 (cited as D-nn), `93-RESEARCH.md` (Patterns 1-4, Pitfalls 1-11, admin structure, checkout details), the Phase 89 contract (`89-UI-SPEC.md`: payment choice tiles, cancellation note, consent labels, admin modal and settings card recipes, reused not reinvented), the Phase 86 admin tokens. The owner was not available in this session: every visual detail not covered by D-nn is a Claude decision, listed in "Claude's Choices".
>
> **Layout reference (D-09).** The GetYourGuide tour page, adapted: one private car per group, price per car, no guide-language selector, no "booked N times", no "likely to sell out", no countdowns, no star rating or review count for the tour (D-14). Only the site's existing reviews block is shown.
>
> **Prices and numbers.** No amount is typed anywhere in this contract, in `app/`, `components/`, `messages/*` or the tour seed content. Every price is a prop from the server (`tours.price_*_eur`, `tour_settings.extra_hour_*_eur`) rendered through `formatEUR` (page, box, cards) or `formatMinor` (checkout, consent, confirmation) and an ICU `{amount}`. Hours, people and percent are ICU parameters (`{hours}`, `{count}`, `{percent}`) filled from the tour row, the tour settings or `VEHICLE_CONFIG`.

## Surface 1 — Tour page (`/{locale}/services/<slug>-day-trip`, 8 locales)

Server-rendered under ISR (`revalidate = 3600`, revalidated on every admin write). `params.locale` + `setRequestLocale`, never `getLocale()`. A locale that is not complete for this tour redirects 307 to the EN URL (D-23); English text never renders under another locale prefix. The page uses the existing `Nav` (fixed, 64px) and `Footer`.

### 1.1 Grid

| Viewport | Container | Columns |
|----------|-----------|---------|
| < 640px | full width, side padding 24px | one column |
| 640 to 1023px | full width, side padding 32px | one column |
| >= 1024px | `max-w-7xl mx-auto`, side padding 48px | 12-column grid, gap 48px: main column `col-span-8`, aside `col-span-4` |

The booking box is rendered **once** (one state) and placed with CSS grid areas:
- below 1024px: areas `"lead" "box" "body"` (one column, the box sits right after the key facts);
- from 1024px: areas `"lead box" "body box"`; the aside wrapper is `position: sticky; top: 88px` (64px nav + 24px) when the viewport is at least 800px high (`@media (min-height: 800px)`), otherwise static so a tall box is never cut off.

## Surface 3 — Booking box and mobile sticky bar (D-10, D-20)

Client component `TourBookingBox`. Props from the server render: tour slug, title, `hours_included`, three class prices, three extra-hour prices, start window (`start_time_min`, `start_time_max`), free-cancel hours, the max people per class from `VEHICLE_CONFIG`. The box never computes a price the server does not recompute (the checkout cross-checks with 409 `PRICE_CHANGED`).

### 3.1 Container

`bg-anthracite-mid`, 1px `--anthracite-light` border, radius 4px, padding 24px; below 640px padding 16px and the box is full width. Vertical rhythm: 24px between field groups, 8px between a field label and its control. `aria-labelledby` the box heading.

### 3.2 Header

"From" 11px/400 `--warmgrey` uppercase, amount Fraunces 24px/400 `--offwhite` in `<bdi>`, "per car" 11px/400 `--warmgrey`. Amount = lowest class price that fits the current passenger count. Once a car is chosen the header is replaced by the total (3.7) and this line disappears, so one price is visible at a time. The box heading (visually the price line) is an `<h2>` with the text "Book this day trip" in a visually-hidden span before the price.

### 3.3 Date

`.label` "DATE". A field button (full width, min-height 44px, `bg-anthracite`, 1px `--anthracite-light` border, radius 4px, padding 12px 16px, `CalendarDays` 16px at the inline end) showing "Choose a date" (`--warmgrey`) or the chosen date via `formatLocaleDate` (`--offwhite`). Click opens an inline panel directly under the field (it pushes the content down; it is not a floating popover, so it works inside the sticky aside and on phones) holding `DayPicker` single month, `mode="single"`, the existing `.rdp-*` dark overrides, `dir` from the page. Disabled days: before today, and any day with no start time at least 12 hours ahead (Prague time, existing lead-time rule). Choosing a day closes the panel and moves focus to the first enabled time chip. Escape closes the panel and returns focus to the field button.

### 3.4 Start time

`.label` "START TIME", hint after the label 11px/300 `--warmgrey` "Prague time". Chips every 30 minutes from `start_time_min` to `start_time_max` inclusive, grid of 3 columns, gap 8px. Chip: min-height 44px, radius 4px, 1px `--anthracite-light` border, 14px/400 `--offwhite`, time in `<bdi dir="ltr">`, 24-hour format in every locale. Selected: 2px `--copper` border, `--copper` text, `aria-pressed` replaced by a `radiogroup` with roving tabindex (arrow keys move and select). Disabled (inside the 12-hour lead time): 40% opacity, `aria-disabled`, not focusable. Before a date is chosen all chips are disabled and the hint line under the grid reads "Choose a date first."

### 3.5 Passengers

`.label` "PASSENGERS". Stepper: `Minus` and `Plus` buttons 44x44 (1px `--anthracite-light` border, radius 4px), the count between them 14px/400 `--offwhite` in an `<output aria-live="polite">`, min 1, max = largest `maxPassengers`; default 2. At the limit the button is disabled. Helper 11px/300 `--warmgrey`: "Children count as passengers. Child seats are free." At the max a second helper with a link: "More than {count} people? Request a custom tour" (link to Surface 6 with `?tour=<slug>&pax=`).

### 3.6 Car

`.label` "CAR". A `radiogroup` of the classes whose `maxPassengers` fits the count, in the order Business, First Class, Business Van. Row: min-height 72px, `bg-anthracite`, 1px `--anthracite-light` border, radius 4px, padding 12px 16px, gap 8px between rows. Inside: car image 72x44 `object-contain` at the inline start (`VEHICLE_CONFIG.image`), then class label 14px/400 `--offwhite` (`Booking.vehicleClasses.*.label`, existing) and the model line 11px/300 `--warmgrey`, `Users` 16px + max people 11px/400 `--warmgrey`; at the inline end the price for that class **including the current extra hours** in Fraunces 24px/400 `--offwhite` in `<bdi>`, with "per car" 11px under it. Selected: 2px `--copper` border, 3px `--copper` bar on the inline start, price in `--copper-light` (VehicleCard recipe). No default selection; when only one class fits (more people than the sedans hold) it is selected automatically. When a class disappears because the count went up, the selection clears and the line "Only cars that fit {count} people are shown." (11px/300 `--warmgrey`) appears under the group.

### 3.7 Extra time and total

`.label` "EXTRA TIME AT THE DESTINATION". Stepper as 3.5, min 0, max 12 (D-20), value text "No extra time" / "+1 hour" / "+{count} hours". Helper 11px/300 `--warmgrey`: with a car chosen "{hours} included. Each extra hour costs {amount} with this car."; without a car "{hours} included. Choose a car to see the price of an extra hour." At 12 the plus button is disabled and the helper adds "For more time, request a custom tour." with the link.

Under it 11px/300 `--warmgrey`: "{hours} at the destination in total" (included plus extra).

### 3.8 Call to action and reassurance

## Accessibility Contract

- **Landmarks and order:** tour page `main` > breadcrumb `nav` > H1 > gallery (`region` "Photos of {title}") > facts `ul` > booking box (`section` labelled by its heading) > content sections (each `section` with its H2). The DOM order equals the mobile visual order; the desktop sticky aside does not reorder the DOM.
- **Booking box:** time chips and car rows are `radiogroup`s with roving tabindex and arrow keys; steppers are buttons plus an `output` with `aria-live="polite"`; the total is `aria-live="polite"`; errors use `role="alert"` and `aria-describedby`; the date panel returns focus on close. The sticky bar is `aria-hidden` while hidden and contains no element focusable while hidden.
- **Gallery and lightbox:** every tile is a button with an `aria-label` ("Open photo {n} of {count}"); the lightbox traps focus, closes on Escape, returns focus, and announces "{n} of {count}" through `aria-live="polite"`. Swipe has a button equivalent.
- **Accordion:** native `button` with `aria-expanded` and `aria-controls`; answers stay in the DOM.
- **Checkout:** Stage B heading receives focus when it opens; Stage A summary has an "Edit details" button; refusal panel is `role="status"`; reused Phase 89 pieces keep their own a11y contract.
- **Admin:** language tabs follow the WAI-ARIA tabs pattern (arrow keys, `aria-selected`, `aria-controls`); completeness is text plus icon, not colour only; Modals trap focus, Escape closes unless busy, initial focus on the safe button for destructive dialogs; list-editor and reorder buttons carry row-specific `aria-label`s.
- **RTL (`ar`):** logical properties only (`margin-inline-start`, `border-inline-start`, `inset-inline-end`, `text-align: start`); chevrons and arrows mirrored with `rtl:-scale-x-100`; carousel and lightbox order follow `dir`; prices, times, references, phones and addresses in `<bdi>` (`dir="ltr"` for times and references, `dir="auto"` for addresses); Latin digits.
- **CJK and Devanagari:** no forced uppercase meaning (labels read correctly without case), no italic display text, `:lang(hi)` line-height increases (Typography).
- **Contrast:** `--offwhite` on `#17293B` about 12:1, `--warmgrey` on `#0F1D2C` about 6.6:1 and on `#17293B` about 5.9:1, `--copper-light` on `#17293B` above 4.5:1 (existing `.label` rationale), `#f87171` on `#17293B` about 5.5:1, "+{count}" `--offwhite` on the 60% navy scrim over a photo at least 4.5:1 (scrim chosen for that).
- **Motion:** card image zoom, sticky bar fade and smooth scrolling are off under `prefers-reduced-motion` (global rule plus explicit `motion-reduce` classes). No autoplay, no countdown, no blinking.
- **Zoom and reflow:** every public surface reads at 320px width and 200% text zoom with no horizontal scroll (the gallery carousel scrolls inside its own box only).

## Claude's Choices (not decided by the owner; recorded for the planner)

1. Desktop layout follows the reference: title and gallery full width, then an 8/4 split with the booking box sticky in the aside; below 1024px the box sits right after the key facts and a sticky bar appears when it scrolls away.
2. One `TourBookingBox` instance placed by grid areas, so mobile and desktop share one state and one set of tests.
3. The date picker opens inline under its field (not a floating popover or a modal), which works inside the sticky aside and on phones.
4. Start times are 30-minute chips between a per-tour earliest and latest start (new `start_time_min` / `start_time_max` fields, editor 7.3 B), 24-hour format in all locales, Prague time.
5. Car rows show the price including the chosen extra hours, so each row always equals what the client pays; no default car, except auto-selection when only one class fits.
6. "Book this trip" is never disabled; missing fields are shown and focused instead.
7. The checkout is one page with two stages (details, then payment) so `/api/card-checkout/init` receives a complete, validated booking body before the card form mounts.
8. The pickup refusal is styled as guidance (copper info panel), not as a red error, and always offers the custom-tour request with tour, date and people prefilled.
9. Box choices survive the round trip to the checkout through `sessionStorage`, so the ISR tour page stays static (no `searchParams`).
10. Photo alt text is generated from the tour title and position in each locale; there are no per-photo, per-locale alt fields.
11. A tour needs at least one photo, a cover and credits for non-own photos before publishing; the last photo of a published tour cannot be deleted.
12. The slug is editable only until the tour is first published (D-07: indexed URLs, no redirects).
13. Photo order uses up/down buttons, not drag and drop (no new dependency; RESEARCH).
14. Tour settings live on `/admin/tours` above the list, not on `/admin/settings`, so everything about tours is on one page.
15. The custom-tour detail is a page, not a side panel; "Create quote" becomes "Open quote {reference}" once a quote is linked (one quote per request; revisions are quote versions).
16. A fixed catalog line on every tour page states that the chauffeur is not a guide and that guides and tickets are not included (package-travel posture, RESEARCH Legal).
17. The hub keeps its JSON shell; the DB tour grid is inserted after "At a glance" and the custom-tour band before the final CTA.
18. No tour delete in this phase (TRIP-05 asks for add, edit, publish, unpublish); unpublish is the only removal.

## API/Schema dependencies the UI relies on (for the planner)

- `tour_translations` needs a `description` text field ("About this trip"), required for completeness, in addition to the RESEARCH data model fields.
- `tours` needs `start_time_min` / `start_time_max` (RESEARCH proposes them) and `drive_minutes_each_way` (required for the "About {hours} in total" fact; publish checklist can treat a missing value as a basics error).
- `tour_photos` needs a `source` value (`own`, `commons`, `unsplash`, `other`) or an equivalent derivation from `license`, so the editor and the credit rules can tell own photos apart.
- Publish refusal codes the editor maps to checklist rows: EN incomplete, no photo, no cover, missing credit, missing price.
- `/api/card-checkout/init` for `tripType: 'tour'` returns the tour policy (free until, percent 100, hours) and an eligibility reason code distinguishing lead time, booking off, tour unavailable and pickup out of area / airport.
- The tour page server render passes: tour row, published locales, photos with credits, three prices, three extra-hour prices, free-cancel hours, start window, and up to 3 related published tours (with cover, title, short description, hours, lowest price) for the page locale.
- The checkout server render passes the pickup radius and the Old Town Square centre for the client-side UX check; the server check stays authoritative.
- A tour confirmation snapshot (ref, title, date, time, pickup address, car, included and extra hours, payment mode, amount label) written before navigating to `/book/confirmation`.
- `/api/custom-tour` answers `{ ok }`, 400 field errors, 422 `INVALID_PHONE`, 429; the success view needs only the email the client typed.
- `/api/admin/custom-tours` list with status derived from `quotes.source_inquiry_id` (open / quoted / erased), the quote id and reference; `/api/admin/quotes` POST accepts `source_inquiry_id` and `locale`.
