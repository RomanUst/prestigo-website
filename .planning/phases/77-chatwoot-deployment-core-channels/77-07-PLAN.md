<interfaces>
Config source: env CHATWOOT_API_TOKEN, CHATWOOT_BASE_URL, CHATWOOT_ACCOUNT_ID; else lines of the same names in ~/.config/prestigo/chatwoot-api.env. Base URL must be https. Header: api_access_token: <token>.

Chatwoot Application API v4.18.0-ce (base /api/v1/accounts/{account_id} unless noted):
- GET /api/v1/profile -> { id, email, ... } (the token owner = "@owner")
- GET/PATCH /api/v1/accounts/{account_id} -> support_email
- GET/POST /labels, PATCH /labels/{id} -> { title, description, color, show_on_sidebar }
- GET/POST /teams, PATCH /teams/{id} -> { name, description, allow_auto_assign }; GET/POST /teams/{id}/team_members { user_ids: [..] }
- GET /custom_attribute_definitions?attribute_model=conversation_attribute|contact_attribute; POST /custom_attribute_definitions { attribute_display_name, attribute_display_type, attribute_description, attribute_key, attribute_model: "conversation_attribute"|"contact_attribute" }; PATCH /custom_attribute_definitions/{id}
- GET/POST /canned_responses, PATCH /canned_responses/{id} -> { short_code, content }
- GET /inboxes -> payload[] { id, name, channel_type, website_token, avatar_url, ... }; POST /inboxes { name, <settings>, channel: { type: "web_widget", ...channel fields } }; PATCH /inboxes/{id} { <settings>, channel: {...} }; avatar via multipart PATCH field "avatar"
- POST /inbox_members { inbox_id, user_ids: [..] }
- GET/POST /automation_rules, PATCH /automation_rules/{id}, DELETE /automation_rules/{id}; body { name, description, event_name, active, conditions: [{ attribute_key, filter_operator, values, query_operator }], actions: [{ action_name, action_params }] }
  channel rule -> event_name conversation_created, conditions [{ attribute_key: "inbox_id", filter_operator: "equal_to", values: [<id>], query_operator: null }], actions [add_label [<label>], assign_team [<team id>], assign_agent [<owner id>]]
  topic keyword rule -> name "topic:<label>:<locale>:<keyword>", event_name message_created, conditions [{ message_type equal_to ["incoming"], query_operator "and" }, { content contains [<keyword>], query_operator null }], actions [add_label [<label>]] (+ assign_team [<B2B id>] for b2b)
  label routing (optional) -> event_name conversation_updated, conditions [{ attribute_key: "labels", filter_operator: "equal_to", values: ["b2b"] }], actions [assign_team [<B2B id>]]; a 4xx on create is reported "skipped (unsupported on this version)" and does not fail the run
Output contract (one line per resource, then summary):
  "<resource>: create=N update=N unchanged=N skipped=N deleted=N" ... "website_token=<public token>" ... "summary: create=N update=N skipped=N"
Exit codes: 0 ok, 1 config/validation error, 2 API error (message = method + path + status + redacted body).
Idempotency: match labels by title, teams by name, attributes by attribute_key+model, canned by short_code, inboxes by name, automation by name (provision-monitors.sh precedent: matched by name, never re-created).
</interfaces>
