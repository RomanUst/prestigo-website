<objective>
Server side of the website chat identity (INBOX-03, D-05): one Next.js route that hands the click-to-load widget its public config (Chatwoot base URL + website token) and, for a signed-in customer, a server-computed HMAC `identifier_hash` so their conversation attaches to their existing contact.

Design choice (Claude's discretion, recorded): the widget's base URL and website token are delivered by this same route instead of being baked into client code. That keeps every VPS host literal and every uppercase CHATWOOT_ env name out of `components/` and `lib/`, so the Phase 76 isolation guard (D-19b, kept green per D-09) needs exactly one allowlist entry — this route, which only runs after the visitor clicks "Chat on site" and never contacts the VPS itself.

Purpose: plan 77-10's launcher fetches this route on click; nothing on page render depends on it.
Output: contract types, server HMAC helper, route handler, tests, one guard allowlist entry.

<interfaces>
Response contract (lib/chat-widget-contract.ts — pure TypeScript, no node: imports, safe to import from client code):
- WIDGET_CONFIG_PATH = '/api/chatwoot/identity'
- type WidgetIdentity = { identifier: string; identifierHash: string; email: string | null; name: string | null; phone: string | null }
- type WidgetConfigResponse = { enabled: false } | { enabled: true; baseUrl: string; websiteToken: string; user: WidgetIdentity | null }
- isSafeWidgetBaseUrl(url: string): boolean — true only for an absolute https: URL whose pathname is '/' or empty, with no search, hash, username or password.

Server helper (lib/chatwoot-identity.ts — imports node:crypto; imported ONLY by the route):
- computeIdentifierHash(secret: string, identifier: string): string — createHmac('sha256', secret).update(identifier).digest('hex')
- buildWidgetConfig(input: { baseUrl?: string; websiteToken?: string; hmacSecret?: string; user: { id: string; email?: string | null } | null; profile: { full_name: string | null; phone: string | null } | null }): WidgetConfigResponse

Route env vars (Vercel Production, set in plan 77-09; read with readEnv from lib/env.ts which strips trailing newlines):
- CHATWOOT_BASE_URL — e.g. the chat subdomain origin, no trailing slash
- CHATWOOT_WEBSITE_TOKEN — public website token of the "Website" inbox
- CHATWOOT_WIDGET_HMAC_SECRET — the Website inbox hmac_token (secret)

customer_profiles columns used: full_name, phone (migration 047), row keyed by user_id; readable by the signed-in user under existing RLS (same query shape as app/[locale]/account/profile/page.tsx).

Guard facts (tests/infra-vps-isolation-guard.test.ts): VPS_ENV_RE = /(?:CHATWOOT|ESPOCRM)_[A-Z0-9_]+/ (case-sensitive), VPS_HOST_RE matches the chat/crm subdomains; BFS taints every importer of a direct-hit file, so a direct hit may live ONLY in a file nothing imports (a route handler). Allowlist entries need a reason of at least 20 characters naming the async mechanism.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /api/chatwoot/identity | untrusted request; identity must come from the Supabase session cookie only |
| Vercel env -> route | server-only HMAC secret; must never cross into a response or client bundle |
| route response -> CDN/edge cache | a cached identity response would leak one user's hash to another |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-77-01 | Spoofing | GET /api/chatwoot/identity | high | mitigate | GET takes no request argument; identifier is always auth.getUser().id; spoof-attempt test case (Task 2) |
| T-77-02 | Information Disclosure | CHATWOOT_WIDGET_HMAC_SECRET | high | mitigate | read only via readEnv inside the route; lib helper takes it as a parameter; tests assert no response body contains the secret or "HMAC_SECRET"; contract file has no node imports so clients never pull the helper |
| T-77-03 | Information Disclosure | edge caching of identity JSON | high | mitigate | force-dynamic + Cache-Control no-store on every branch, asserted per branch in tests |
| T-77-04 | Denial of Service | page render depending on the VPS | low | mitigate | route only reads env and hashes locally, is fetched only after a click, and fails closed to {enabled:false}; guard test keeps every other file free of VPS references |
| T-77-SC | Tampering | npm/pip/cargo installs | high | mitigate | no package installs in this plan (node:crypto built-in); package-legitimacy gate not triggered |
</threat_model>
