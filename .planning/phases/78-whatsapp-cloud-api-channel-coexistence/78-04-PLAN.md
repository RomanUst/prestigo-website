Expansion per windowRule (RESEARCH "Delayed window rules", facts quoted from Chatwoot v4.18.0):
- delayed rule: name = rule.name, event_name message_created, active true, execution_delay = delayMinutes, optional true, conditions [ inbox_id equal_to ["@inbox:<inbox>"] query_operator "and", message_type equal_to ["incoming"] query_operator null ], actions [ add_label [label] ]
- clearing rule: name = rule.clearName, event_name message_created, active true, not optional, conditions [ inbox_id equal_to ["@inbox:<inbox>"] "and", message_type equal_to ["outgoing"] null ], actions [ remove_label [label] ]
Chatwoot facts: EXECUTION_DELAY_RANGE 10..43200 minutes; delayed rules need the account feature delayed_automations (off by default; the controller rejects execution_delay while off -> 4xx -> the existing optional skip); any human reply, including a phone echo, clears waiting_since and cancels the pending delayed run; delayed rules do not support attribute_changed.
buildInboxRefs(inboxes, config) already maps a managed name to the single existing inbox of the same channel_type when exactly one managed entry has that type (Telegram precedent); ensureOwnerInboxMember(ctx, inboxId, ownerId) returns true when it added the owner.
