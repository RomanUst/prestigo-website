<objective>
The data path both new views share: an admin-only range route over the existing search RPC, and a client hook that polls it every 30 seconds with the D-16 pause rules, plus the "Updated N s ago" ticker.

Tracer: the hook loads one range from the new route on mount and exposes the rows; the route answers that range through auth, validation and the RPC.

Purpose: DISP-01 needs bookings for a chosen date range (the list GET caps at 100 per page and sorts by created_at); DISP-05 needs driver steps to appear without reload. Driver steps already write through the status service, so polling picks them up with no extra wiring.
Output: one route, one hook, one ticker component, two test files. The route commit carries the `security:` prefix (CLAUDE.md: auth + validation).
</objective>
