<research_correction>
**RESEARCH Pattern 2 / PATTERNS "Horizon → date-range" snippets have horizon OVERRIDE the
manual startDate/endDate** (`let resolvedStartDate = startDate ?? null; if (horizon) { resolvedStartDate = today }`).
That contradicts **D-07** ("explicit dates take precedence over the horizon-derived window
for that session"). Implement D-07 instead: apply the horizon branch ONLY when neither an
explicit `startDate` nor `endDate` is present; when either is present, use the manual bounds
as-is and leave sort at 'created_desc'. This also keeps the KPI fetches (which always pass
explicit startDate+endDate and no horizon) untouched (D-05, verified in Plan 65-04).
</research_correction>
