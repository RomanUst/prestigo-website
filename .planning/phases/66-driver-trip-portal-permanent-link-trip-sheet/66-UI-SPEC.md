## Spacing Scale

Declared values (must be multiples of 4), matching the existing driver-facing card pattern:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, tight inline spacing |
| sm | 8px | Field-grid row/column gap (`gap: 8px 16px` on the label/value grid) |
| md | 16px | Default spacing between sections/rows |
| lg | 24px | Sub-heading-to-content spacing |
| xl | 32px | Card padding (vertical), wordmark-to-heading spacing |
| 2xl | 48px | Card padding (horizontal) — matches existing `padding: '32px 48px'` |
| 3xl | 64px | Not used on this page (single-card layout has no page-level section breaks) |

Exceptions:
- Buttons (both the driver-facing area, if any control appears, and the admin "Copy Trip Link" control) use `minHeight: 44px` as an accessible touch-target floor — matches `DriverAssignmentSection.tsx`'s existing `assignButtonStyle`/`reassignButtonStyle` (44px) and `DriverResponseClient.tsx`'s accept/decline buttons (56px). Use **44px** for the admin copy-link control (secondary action, admin desktop context) and reserve 56px for any full-width driver-facing tap target (none introduced in Phase 66, since it is view-only).
- Map container height is a fixed non-8pt value driven by aspect ratio (e.g. `280px` or `320px` mobile-first) rather than the spacing scale — map dimensions are a media-sizing concern, not a spacing token.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 300 | 1.5 |

Weights declared (exactly 2, matching existing codebase convention):
- **300** (light/regular) — body copy, labels, display title. This is the dominant weight throughout `app/driver/response/page.tsx` and `DriverAssignmentSection.tsx`.
- **500** (semibold) — section headings, button labels, the booking-reference emphasis text. Matches existing `fontWeight: 500` on `assignButtonStyle`/accept-decline buttons.

Font-family mapping: Display/Heading → `var(--font-cormorant)` (Fraunces). Body/Label → `var(--font-montserrat)` (Inter). Do not introduce a third font.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (admin) | "Copy Trip Link" (icon: `Copy` from lucide-react; swaps to "Copied!" for 2s on success, matching `DriverResponseClient`'s state-swap pattern) |
| Empty state (map, missing coordinates) | "Map unavailable — see address above." (adapts `RouteMap.tsx`'s existing "Route unavailable — you can still select a vehicle class." empty-state copy for the trip-sheet context; text pickup/dropoff address rows still render regardless) |
| Error state (invalid/expired/reassigned/unknown token) | "This trip link is no longer active." — uniform, neutral, NO distinction between "unknown token" and "invalidated token" (D-11). No booking data shown. Tone matches the existing `/driver/response` "This link has expired or has already been used." card, styled with `var(--warmgrey)`, not destructive red. |
| Error state (admin clipboard copy failure) | "Couldn't copy — select and copy the link manually." Falls back to a selectable read-only text field containing the full URL. |
| Destructive confirmation | Not applicable — Phase 66 introduces no destructive actions (no revoke/delete UI; token invalidation is automatic via D-03's status/reassignment predicate, not a manual operator action). |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Elements classified: **Trip detail fields** (kind: `form` — a fixed, non-editable set of labeled fields with real partial-data and long-text risk), **Embedded map** (kind: `media`), **Admin "Copy Trip Link" control** (kind: `interactive-control`), **Invalid trip-link placeholder** (kind: `static-content`, fixed system copy — no state considerations raised, dismissed as out-of-scope for length/overflow).

Applicable state considerations resolved: 8 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| partial | Trip detail fields | ✅ covered | Null/empty optional fields (flight info, special requests, driver `vehicle_info`) are omitted as whole rows rather than rendered blank or as "N/A" — keeps the trip sheet clean and unambiguous for police-control legibility (Pitfall 4 requires showing both `bookings.vehicle_class` and `drivers.vehicle_info` distinctly when present). |
| long-text | Trip detail fields — `special_requests` | ✅ covered | Renders as wrapped body text (`white-space: normal`, no truncation/ellipsis) — the full note must stay legible since the page is presentable to police control. |
| error | Trip detail fields — orphaned/missing joined booking | ✅ covered | If `trip_token` resolves a `driver_assignments` row but the joined `bookings` row is unexpectedly missing, treat identically to an invalid token — render the same neutral placeholder (D-11), never a raw error page or stack trace. |
| empty | Embedded map — missing coordinates | ✅ covered | When `origin_lat/lng` or `destination_lat/lng` is `null`, reuse `RouteMap.tsx`'s existing null-safe empty state, copy adapted to "Map unavailable — see address above." Text pickup/dropoff address rows render independently of map success (Pitfall 3 — pass `null`, never `{lat:0,lng:0}`). |
| loading | Embedded map — Google Maps JS SDK loading | 🧪 backstop | Map container shows the card-surface color (`var(--anthracite-mid)`) as a placeholder background while the SDK loads client-side; sub-second in practice, so no spinner is specified. This is a visual-only claim — verify by screenshot/manual check, not asserted by a unit test. |
| error | Embedded map — SDK fails to load | ✅ covered | Address text rows (From/To) are independent static content, not conditioned on map success — a failed map load never removes the police-control-relevant address text; only the visual map panel is affected. |
| populated | Embedded map — normal draw | ✅ covered | Reuses `RouteMap.tsx` as-is: polyline + origin/destination markers, attribution-safe rendering (Google logo/"Terms" links are never hidden — confirmed by reading the component's render tree this session; see project memory "Google Maps attribution hidden — ToS risk"). |
| error | Admin "Copy Trip Link" control | ✅ covered | On `navigator.clipboard` write failure (e.g. non-secure context), falls back to a selectable read-only text input containing the link so the dispatcher can copy manually — see Copywriting Contract "Couldn't copy" row. |
| loading | Admin "Copy Trip Link" control | ✅ covered | Button label swaps to "Copied!" for 2s after a successful clipboard write — matches the existing `DriverResponseClient` button-state-swap pattern ("Confirming..." → done state). |

## Appendix: Content Structure Notes (from CONTEXT.md D-05/D-06/D-07, for planner/executor reference)

**Header (D-05):** Prestigo wordmark (reuse `.wordmark` class), then the display title "Trip Sheet", then the booking reference shown prominently directly below (e.g. as a copper-accented monospace-feeling label/value pair) — must read as an official, presentable document.

**Section order (D-06), grouped under Heading-styled dividers:**
1. **Trip Details** — pickup date, pickup time, from address, to address, flight info (omit row if null).
2. **Passenger** — first + last name, phone, special requests (omit row if null; wrap, never truncate).
3. **Route Map** (D-07) — embedded `RouteMap.tsx` instance built from `bookings.origin_lat/lng` + `destination_lat/lng` (nullable — see UI Considerations "empty" row).
4. **Vehicle & Driver** — booked `vehicle_class` (formatted via `formatVehicleLabel()`, export it from `lib/email.ts` per research Don't-Hand-Roll), driver's `vehicle_info` (free text, distinct label — Pitfall 4), driver name + phone.

**Invalid-link view:** single centered card, wordmark + neutral message only (Copywriting Contract), no data, no distinguishing detail between failure reasons (D-11).

**Admin "Copy Trip Link" control (D-10):** placed inside `DriverAssignmentSection.tsx`'s existing "assigned" render branch, next to the driver name/status badge — a small icon+label button (`Copy` lucide icon), 44px min height, copper-accent border, matching the existing `reassignButtonStyle` visual weight (not the more prominent solid `assignButtonStyle`).
