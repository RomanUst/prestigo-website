## Theme Architecture (contract)

1. **Scope (D-02).** Theme and sidebar state are attributes on one admin wrapper element, never on `<html>`/`<body>`:
   `<div class="admin-shell" data-admin-theme="light|dark" data-admin-sidebar="expanded|collapsed" style="--admin-sidebar-w: 280px|72px">`.
   The wrapper also sets `color-scheme: light|dark` so native date inputs, selects and scrollbars match the theme.
2. **Where it lives.** A server layout reads cookies `admin_theme` and `admin_sidebar` via `cookies()` and renders the wrapper (the `(dashboard)/layout.tsx` is already dynamic, so this costs nothing). A thin client component owns the toggle state and updates the wrapper attributes immediately on click, so no `router.refresh()` is needed. The login route gets its own server layout that renders the same wrapper (D-18).
3. **Cookies (D-01).** `admin_theme` = `light|dark`, `admin_sidebar` = `expanded|collapsed`. Attributes: `Path=/admin; Max-Age=31536000; SameSite=Lax; Secure` (Secure in production), not HttpOnly (client writes them). Missing or invalid value falls back to `light` / `expanded` (D-06). No `next-themes`, no inline script.
4. **No flash, no layout shift.** The server renders the final attributes and the final `--admin-sidebar-w` into the first HTML. CSS transitions apply only to later changes (nothing animates on load).
5. **CSS file.** All token definitions (hex/rgb values) live in a single new stylesheet outside the guarded TS/TSX paths (recommended `app/(internal)/admin-theme.css`, imported from `app/(internal)/layout.tsx`; planner may choose `globals.css`). Every rule is selector-scoped to `.admin-shell`. `.theme-light` is NOT edited (D-05), and no rule targets `html`, `body` or any unscoped selector, so public pages and all 7 locales are unaffected. Existing golden-HTML/snapshot tests of public pages must stay green with no snapshot edits.
6. **Remap of legacy vars.** Inside `.admin-shell[data-admin-theme="light"]` re-declare the bare `--anthracite*`, `--copper*`, `--offwhite`, `--warmgrey` to the light values below, so the ~900 existing `var(--…)` references flip for free. New code uses the semantic `--admin-*` / `--status-*` tokens only.
7. **Light-only structural differences (D-08).** Chosen mechanism (planner may refine, outcome is fixed):
   - Shared primitives (`labelStyle`, `inputBaseStyle`, `Modal`, `StatusBadge`, `KPICard`, table styles) consume tokens for radius, label transform, label tracking, heading font and shadow.
   - Heading font: convert every inline `var(--font-cormorant)` in admin code (except the PRESTIGO wordmark) to `var(--admin-font-heading)`; light = Inter, dark = Fraunces.
   - Safety net for the many scattered inline labels, scoped under `.admin-shell[data-admin-theme="light"]` only: `[style*="text-transform: uppercase"] { text-transform: none !important; letter-spacing: normal !important }` and `[style*="font-weight: 300"] { font-weight: 400 !important }`. Dark theme never receives these rules.
8. **Portals / third-party surfaces.** Modals render inside the wrapper (no portal), so they inherit tokens. Recharts tooltip and Google Maps surfaces must be fed token values explicitly (see Charts and map).

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between stacked nav items (light), icon-to-badge dot, label-to-input |
| sm | 8px | Compact element spacing, tooltip offset from rail, chip padding (vertical 4 / horizontal 8) |
| md | 16px | Default element spacing, sidebar section padding, modal header margin |
| lg | 24px | Card padding, modal padding (dark), sidebar header padding |
| xl | 32px | Main content side/bottom padding (unchanged), modal padding (light), layout gaps |
| 2xl | 48px | Login card vertical padding (unchanged) |
| 3xl | 64px | Mobile main top padding `pt-16` (unchanged, clears the hamburger) |

Existing in-use `12px` (nav icon-to-label gap, input horizontal padding) is a multiple of 4 and is retained.

Exceptions:
- Sidebar widths: expanded 280px, collapsed rail 72px (D-13), driven only by `--admin-sidebar-w`.
- Touch targets: nav links, toggles, sign out and hamburger keep `min-height: 44px` / `min-width: 44px` (WCAG 2.5.5; also asserted by `tests/AdminSidebar.test.tsx`). Light theme gets compactness from 14px type and 4px row gap, not from smaller targets.
- Icons are 20px in the rail and nav (sun/moon/collapse 20px; hamburger stays 20px).
- 1px borders/dividers; 2px focus outline offset.
- Margin transition on `main`: `margin-left 200ms ease`, disabled under `prefers-reduced-motion: reduce`.
- Z-index stack (unchanged order): sidebar 50 < mobile hamburger 60 < rail tooltip 70 < modal 100.

## Typography

Four sizes and two weights per theme. Dark keeps today's 11/13 scale; light uses the calmer 12/14 scale (D-09, D-10). Sizes are exposed as tokens (`--admin-fs-label`, `--admin-fs-body`, `--admin-fs-heading`, `--admin-fs-display`) that new and restyled code references; this phase does not re-type every inline `fontSize`, only shared primitives, the shell and the elements named below.

| Role | Light | Dark | Weight | Line Height |
|------|-------|------|--------|-------------|
| Label / meta (table headers, field labels, chip, sub-label, tooltip) | 12px, sentence case, tracking 0 | 11px, UPPERCASE, existing tracking | 500 (field labels, table headers, chips) / 400 (sub-labels) | 1.4 |
| Body (nav, table cells, inputs, buttons) | 14px | 13px | 400 (500 for the active nav item and primary button) | 1.5 |
| Heading (page title, modal title, card title) | 20px, Inter | 20px, Fraunces | 500 light / 300 dark (legacy, unchanged) | 1.2 |
| Display (KPI value, login title) | 28px, Inter | 28px, Fraunces | 500 light / 300 dark (legacy) | 1.1 |

Rules:
- Declared weights are 400 and 500. The legacy weights 300 (dark headings) and 600 (3 usages) are not extended to any new element; in light, 300 is forced to 400 by the safety net, and the three 600 usages are changed to 500.
- KPI value was 32px; it becomes 28px (Display token) in both themes to keep a 4-size scale.
- PRESTIGO wordmark: Fraunces 20px, tracking 0.12em, uppercase, weight 400 in both themes (brand mark, exempt from the light-theme sentence-case rule). The "Admin" sub-label under it is hidden in the collapsed rail.
- Light theme: no uppercase and no letter-spacing on labels or headings (D-10); thin 1px dividers (`--admin-border`) instead of boxes.

## Shell Components and Interaction Contract

### Sidebar (`components/admin/AdminSidebar.tsx`)

| Aspect | Expanded (280px) | Collapsed rail (72px, desktop only) |
|--------|------------------|--------------------------------------|
| Header | `PRESTIGO` wordmark + "Admin" sub-label; collapse button at the right edge (D-14) | Collapse button only, centered; wordmark and sub-label hidden |

| Active item | `aria-current="page"`; light = `--admin-sidebar-active` fill, ink text, weight 500; dark = current look (left bar, offwhite text) | Same fill on the icon tile |
| Hover | `--admin-sidebar-hover` fill, 150ms colour transition | Same, plus tooltip |
| Footer | Theme toggle (icon button) and Sign out (LogOut icon + "Sign out") on one row | Theme toggle and Sign out icon buttons stacked, each with tooltip |
| Overflow | Nav list scrolls (`overflow-y: auto`) on short viewports; footer stays pinned | Same |

- Nav icons (11 items, order and hrefs unchanged, `Map` imported as `MapIcon` to avoid shadowing the global): Pricing `Tag`, Zones `Map`, Bookings `CalendarCheck`, Accounts `Building2`, Drivers `Car`, Promos `Ticket`, Settings `Settings`, Stats `ChartColumn`, Outbox `Send`, Identities `IdCard`, Erasure `Eraser`.
- Collapse toggle: `PanelLeftClose` when expanded, `PanelLeftOpen` when collapsed; `aria-expanded`, `aria-controls="admin-sidebar"`. Click writes `admin_sidebar`, flips `data-admin-sidebar` and `--admin-sidebar-w`; `main` margin is `md:ml-[var(--admin-sidebar-w)]` with the 200ms transition (replaces `md:ml-[280px]`).
- Theme toggle: shows `Sun` while dark (action: go light) and `Moon` while light (action: go dark); the label always names the action. Click writes `admin_theme` and flips `data-admin-theme` instantly with no reload.
- Keyboard (D-15): `Ctrl+\` or `Cmd+\` toggles collapse and calls `preventDefault`. Ignored when focus is in `input`, `textarea`, `select` or a `contenteditable` element, and while a modal is open. Desktop only.
- Tooltips (collapsed rail only): one small CSS tooltip per item, shown on hover and on `:focus-visible`, 300ms hover delay, placed 8px to the right of the rail, `white-space: nowrap`, z-index 70, `--admin-tooltip-bg/fg`, 12px/500 type. Not the native `title` attribute (no keyboard support, inconsistent delay). Icon-only controls always carry `aria-label`.
- Mobile (D-16): below `md` nothing changes structurally — hamburger (44x44, top-left, z 60) plus a 280px slide-over that always shows full labels regardless of the cookie; the panel closes on navigation and on backdrop tap. The collapsed state never affects mobile. Hamburger and backdrop use `--admin-sidebar-bg`, `--admin-border-strong`, `--admin-text`, `--admin-scrim`.
- Existing assertions in `tests/AdminSidebar.test.tsx` must keep passing (open-menu label, `md:hidden` on the hamburger, nav order, hrefs, inline `min-height` on every link); the tests are updated only to supply the new props.

## Guard Test Contract (D-04, ADM-03 criterion 4)

New test (e.g. `tests/admin-no-hardcoded-colors.test.ts`):
- Scans every `.ts`/`.tsx` under `components/admin/**` and `app/(internal)/admin/**`.
- Fails on: `#RGB`, `#RGBA`, `#RRGGBB`, `#RRGGBBAA` literals (match only where preceded by a quote, space, `(` or `:` to avoid anchors such as `#section`), `rgb(`/`rgba(`/`hsl(`/`hsla(`/`oklch(` literals, and bare CSS colour keywords used as colour values (`white`, `black`, `red`, …) in `color`, `background*`, `border*`, `fill`, `stroke` properties.
- Allowlist: an explicit array of `{ file, reason }` entries in the test file (initially empty). Any addition requires a reason string and shows in code review. Token definitions are in the CSS file, outside the scanned paths.
- The failure message names the file, line, literal and the nearest token from the Token Map.
- Companion test: the theme stylesheet defines every `--admin-*`/`--status-*` token used in admin code for both `data-admin-theme` values (parses the CSS and the TSX var references), so a token cannot exist for one theme only.
