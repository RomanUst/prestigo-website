<interfaces>
API contract (implemented by plan 88-15; this plan codes against it):
GET /api/admin/bookings/{id}/payment -> 200
{
  payment: { mode: PaymentMode; state: PaymentState; currency: 'eur' | 'czk' | null; amount_minor: number | null; hold_amount_minor: number | null; captured_amount_minor: number; hold_at: string | null; capture_before: string | null; card_saved: boolean; last_payment_error: string | null; payment_retry_at: string | null; payment_retry_count: number; recovery_link_url: string | null; pickup_at: string | null; status: string; completed: boolean; booking_reference: string; client_email: string | null },
  allowed_actions: Array<'capture' | 'retry' | 'release' | 'waive' | 'send_link'>,
  refund_failed: boolean,
  events: Array<{ id: number; created_at: string; kind: string; amount_minor: number | null; currency: string | null; actor_type: 'system' | 'webhook' | 'admin'; actor_id: string | null; error_code: string | null }>,   // newest first, at most 100
  events_total: number
}
POST /api/admin/bookings/{id}/payment body { action: 'capture' | 'retry' | 'release' | 'waive' | 'send_link' } -> 200 { outcome: 'ok' | 'declined' } | 409 { error: 'payment_busy' } | 422 { error: 'action_not_allowed' } | 401 | 403 | 404
Cancel route (plan 88-16): 502 { error: 'refund_failed', cancelled: true, amount_minor?, currency? } when the cancel applied but the refund or release failed; 409 { error: 'status_conflict', currentStatus } now means nothing was refunded.
Admin PATCH trip edit (plan 88-16): success body may carry payment_effect: { kind: 'amount_raised' | 'amount_lowered' | 'hold_released'; currency: 'eur' | 'czk'; held_minor?: number; diff_minor?: number; amount_minor?: number; hold_date_iso?: string } ; 409 { error: 'payment_in_progress' }.
