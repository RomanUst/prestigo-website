<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client form → server action | FormData is fully untrusted; it may carry forged user_id, extra fields, or hostile strings. The action is the validation/ownership boundary. |
| authenticated user → own customer_profiles / saved_passengers rows | A user must not read or mutate another user's profile or passengers. |
| passenger name → rendered HTML | User-controlled strings (passenger name/notes) are displayed back. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-58-13 | Elevation of Privilege (IDOR) | updateProfile / passenger actions | mitigate | Ownership derived from supabase.auth.getUser(); any user_id in FormData is never read; writes are .eq('user_id', user.id) and backed by own-row RLS on both tables (D-05/D-06/D-07). deletePassenger scopes by id AND session user_id. |
| T-58-14 | Tampering (mass assignment) | updateProfile / updatePassenger | mitigate | Actions name each updatable column explicitly (full_name, phone, account_type, company_name, ico, vat_id / passenger fields); raw FormData is never spread into the update object. |
| T-58-15 | Tampering (CSRF) | profile/passenger mutations | mitigate | Server actions use same-origin cookies with SameSite=Lax; they do not go through a CSRF-exempt API prefix (RESEARCH Don't Hand-Roll / Security Domain). No additional token needed. |
| T-58-16 | Tampering (XSS) | passenger name/notes display in ProfileForm | mitigate | Rendered via React JSX (auto-escaped); no dangerouslySetInnerHTML; aria-labels built by string concat are also JSX-escaped. |
| T-58-17 | Tampering (data integrity) | is_default single-default | mitigate | Partial unique index (Plan 02) enforces a single default atomically; the action clears other defaults before setting one and maps a unique-violation to a user-facing error (RESEARCH Pattern 5 / Pitfall 3). |
| T-58-18 | Information Disclosure | profile data load | mitigate | The /account/profile server component reads only .eq('user_id', user.id) rows under own-row RLS; force-dynamic + middleware gate prevent unauthenticated access. |
| T-58-SC | Tampering | npm/pip/cargo installs | accept | No package installs — RESEARCH Package Legitimacy Audit confirms zero new packages. |
</threat_model>
