<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry -> repo | third-party code enters the server bundle |
| browser -> push subscribe route | subscription JSON is attacker-controllable |
| server -> push services (FCM, Mozilla, *.push.apple.com) | outbound encrypted payloads signed with the VAPID private key |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-94-SC | Tampering | npm install of web-push / @types/web-push | high | mitigate | blocking-human legitimacy checkpoint (Task 1), exact pins 3.6.7 / 3.6.4, no postinstall, 4.0.0 avoided as too new |
| T-94-24 | Tampering | subscribe route (SSRF via a crafted endpoint) | medium | mitigate | endpoint must be an https URL of at most 1000 chars (zod + DB CHECK); the server only POSTs encrypted payloads to it through web-push; no response body is read back into the app |
| T-94-25 | Spoofing | subscribing for another driver | medium | mitigate | driver_id is always taken from getDriverSession(), never from the body; DELETE filtered by driver_id |
| T-94-26 | Information disclosure | push endpoints, keys or payload in logs | medium | mitigate | logs carry only the status code; grep gate on console calls naming endpoint |
| T-94-27 | Information disclosure | VAPID private key | high | mitigate | generated inside the owner script, piped to Vercel without printing, never committed (pre-commit secret scan), read at runtime via readEnv |
| T-94-28 | Denial of service | push send failures breaking the caller | low | mitigate | Promise.allSettled + catch-all; sendDriverPush never throws; 404/410 pruned |
</threat_model>
