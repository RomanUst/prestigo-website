> **Checker notes (approved 2026-11-25, non-blocking FLAGs folded in):** the 4-size / 2-weight cap applies per surface
> (cabinet; admin theme and email keep their own pre-existing scales). Card buttons read "Accept ride" / "Decline ride",

> ride detail = map; You = name.

> Visual and interaction contract for the Driver Cabinet: sign-in, the three tabs (Rides, Offers, You), the ride detail, the offer email, the offer push notification and the admin drivers-list additions. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Layout reference is a typical ride-hailing driver app (bottom tabs, ride list grouped by day) only: no copied names, assets, icons or look-alike branding (D-02).

## Theme Architecture (contract)

1. **Always light (D-02).** Every cabinet route renders inside `<div className="admin-shell driver-shell" data-admin-theme="light">`, exactly as the trip screen does. No cookie is read, no toggle exists. A phone in system dark mode still shows the cream theme.
2. **Where it lives.** New route group `app/(internal)/driver/(cabinet)/` with its own `layout.tsx` (imports `admin-theme.css`, `driver-trip.css`, `driver-cabinet.css`, renders the wrapper above, sets `metadata.manifest`, `appleWebApp`, `icons.apple`, `viewport.themeColor`). `/driver/login` uses the same wrapper but not the tab bar. `/driver/response` and `/driver/trip/*` keep their current layouts (D-15, not restyled).
3. **Column.** One centered column, `max-width: 480px`, `margin: 0 auto`, `min-height: 100dvh`, `display: flex; flex-direction: column`. At >= 768px the column gets 1px `--admin-border` side rules; the rest stays cream. No separate desktop layout.
4. **Colour rule.** TSX under `app/(internal)/driver/(cabinet)/**`, `app/(internal)/driver/login/**` and any `components/driver/**` uses only `var(--admin-*)` and `var(--status-*)`. The PWA manifest route (`app/(internal)/driver/manifest.webmanifest/route.ts`) is the one place that must write literals (`theme_color` / `background_color` `#EFE8DA`, the cream `--admin-bg`); it sits outside the guarded roots. Email HTML lives in `lib/email.ts` (outside the guard) and uses the existing brand navy/gold literals.
5. **Pages are private and per-request.** `export const dynamic = 'force-dynamic'`, no-store; every page and route calls `requireDriver()` itself (research Pitfall 4).
6. **PWA surface.** `display: standalone`, `start_url: /driver/rides`, `scope: /driver/`. Status bar style `default` (dark text on cream). The app icons are **new** brand-navy assets (see "Push notification and PWA assets"); the existing `/brand/logo-*.png` files are the retired anthracite/copper look and must not be reused.

## Shell and Navigation

### Header (tab pages and login)

Height 56px, `--admin-bg`, horizontal padding 24px. PRESTIGO wordmark (`.admin-wordmark`, Fraunces 20px, tracking 0.12em, weight 400) left on tab pages, centered on login. No Help button on tab pages (Help lives in You). Under the header, each tab page has its **page title**: Display 28/500, `--admin-font-heading`, margin `8px 24px 16px`.

### Bottom tab bar (`CabinetTabBar`)

`<nav aria-label="Cabinet">`, last child of the column, `position: sticky; bottom: 0`, `--admin-surface`, 1px `--admin-border` top, bottom padding `env(safe-area-inset-bottom)`, content height 64px. Three equal links: **Rides** (`CalendarDays`), **Offers** (`Inbox`), **You** (`User`). Each link: `display:flex; flex-direction:column; align-items:center; justify-content:center; gap:4px`, min height 64px (>= 48px target), icon 24px, label Label 12/500.

| State | Icon + label colour | Extra |
|-------|--------------------|-------|
| inactive | `--admin-text-muted` | none |
| active (`aria-current="page"`) | `--admin-accent-text` | 2px `--admin-accent` bar along the top edge of the link |
| pressed | `--admin-hover` background | none |
| focus | 2px `--admin-focus` ring, 2px offset (`data-driver-focus`) | none |

**Offers badge:** when the driver has `n >= 1` live offers, a 20px-high pill (min-width 20px, padding 0 4px, radius 10px) overlaps the top-right of the Offers icon: `--admin-accent` fill, `--admin-on-accent` text, Label 12/500, tabular numerals, text `n` (`9+` above 9). The link's accessible name is `Offers, {n} new` (no badge text read twice: the badge is `aria-hidden`). No badge at 0. The tab bar is hidden on the ride detail and on the sign-in page (the detail is full-screen like the trip screen).

### Freshness

`CabinetRefresh` client island in the tab layout calls `router.refresh()` on: `visibilitychange` to visible, the `online` event, and every 30s while the page is visible. Client state (open dialog, push toggle) survives. No polling endpoint is added.

### Session end

Any cabinet page without a valid session (expired, signed out, disabled) redirects to `/driver/login?next=<safe path>`. A client action that gets 401 closes its dialog and navigates to the same URL; the login page then shows the line "Your session ended. Sign in again." (shown when `?ended=1`).

## Screen Contract: Sign-in (`/driver/login`)

Public page. A valid session redirects away (to `next` or `/driver/rides`). `next` is accepted only if it starts with `/driver/` (never `//`, never `/driver/login`). Content column: padding 24px, gap 16px, content starts 48px below the header.

**Step 1: email.**
- Heading Display 28/500 "Sign in". Body 16/400 `--admin-text-muted`: "Enter the email the office has on file for you. We will send you a 6-digit code." When `next` starts with `/driver/offers` the body is replaced by "Sign in to see your new ride offer. We will send a 6-digit code to your email."
- Field: label Label 12/500 "Email" above; `<input type="email" inputmode="email" autocomplete="email" autocapitalize="none" autocorrect="off" spellcheck="false">`, 48px high, Body 16/400 (no iOS zoom), `--admin-input-bg`, 1px `--admin-border-strong`, radius `--admin-radius-md`, padding 0 16px, `maxLength` 254. Auto-focus on desktop only (not on touch, to avoid the keyboard covering the screen on load).
- Primary button "Send code": full width, 48px, `--admin-accent` fill, `--admin-on-accent` text, Body 16/500, radius `--admin-radius-md`. Disabled until the field contains `@`. Submitting: `LoaderCircle` + "Sending…", `aria-busy`, field disabled.
- **The answer is identical for every email** (registered, not invited, disabled, unknown): the page always moves to step 2. Nothing on screen reveals whether the email exists (DCAB-01).
- Errors (`role="alert"`, `--status-danger-fg`, Body 16/400, under the button): invalid format "Enter a valid email address."; 429 "Too many attempts. Wait a few minutes and try again."; network or 5xx "Could not send the code. Check your connection and try again."

**Step 2: code.**
- Heading Display 28/500 "Enter your code". Body 16/400 muted: "If **{email}** is set up for the cabinet, we sent a 6-digit code. It works for 10 minutes." (email in weight 500, `overflow-wrap: anywhere`).
- Code field: label "6-digit code"; one `<input type="text" inputmode="numeric" autocomplete="one-time-code" pattern="[0-9]*" maxLength={6}>` (single field so email/OS autofill and paste work), 56px high, centered, Display 28/500 tabular numerals, **letter-spacing 0.25em (declared exception, digit legibility; code field only)**, same border/background as the email field. Non-digits are stripped on input. Reaching 6 digits submits automatically; the button below is the fallback.
- Primary button "Sign in" (same style as above); submitting: "Signing in…" with `LoaderCircle`, field disabled. Success: redirect to `next` or `/driver/rides` (full navigation so the cookie is read).
- Errors (`role="alert"`, danger text; the field keeps focus and is cleared): wrong code "That code is not correct. Check it and try again."; expired, used or too many wrong tries "This code has expired or was used too many times. Send a new code."; 429 "Too many attempts. Wait a few minutes and try again."; network "Could not sign in. Check your connection and try again."
- Secondary controls, stacked, gap 8px: **"Send a new code"** (neutral outline, 48px) disabled for 30s after each send with the label "Send a new code in 0:24" (Label 12 countdown is part of the label; UI courtesy only, the server limit is the real control); after a resend a `role="status"` line "A new code is on its way." **"Use a different email"** (text button, `--admin-accent-text`, Body 16/500, 48px hit area) returns to step 1.
- Footer line, Label 12/400 muted, centered: "No code? Check your spam folder, or ask the office to set up your access." followed by the `tel:` link "Call the office" (`--admin-accent-text`, 48px hit area), same `BUSINESS_TEL_URL` / `BUSINESS_PHONE_DISPLAY` as the trip screen.
- Inside a Home Screen (standalone) launch the page works identically and keeps `next`.

## Screen Contract: Rides (`/driver/rides`)

Page title "Rides". Below it a **view switch**: two links "Upcoming" / "Past" in a segmented control (`<nav aria-label="Rides view">`, links with `aria-current="page"`; the URL decides: `/driver/rides` and `/driver/rides?view=past&month=YYYY-MM`). Track: height 48px, margin 0 24px, `--admin-hover` fill, 1px `--admin-border-strong`, radius `--admin-radius-md`, padding 4px, two equal segments. Selected segment: `--admin-surface` fill, 1px `--admin-border-strong`, Body 16/500 `--admin-text`; unselected: transparent, Body 16/400 `--admin-text-muted`. (Not accent: the switch is neutral.)

### Upcoming

Rides of this driver whose assignment is accepted (or pending with the booking already started) and whose booking is not terminal, ascending by pickup instant, grouped by **Prague date**.

- **Day header** (`DayGroupHeader`): Label 12/500 `--admin-text-muted`, padding `24px 24px 8px`, not sticky, `<h2>`. Text: `Today`, `Tomorrow`, otherwise `Fri 27 Nov`; the year is added (`Fri 8 Jan 2027`) only when it differs from the current Prague year. Dates are Prague calendar dates, never browser-local.
- **Ride row** (`RideRow`): one `<a href="/driver/rides/{assignmentId}">` card, margin `0 24px 8px`, padding 16px, `--admin-surface`, 1px `--admin-border`, radius `--admin-radius-md`, min height 80px, no shadow, `ChevronRight` 20px `--admin-text-muted` vertically centered at the right. Pressed `--admin-hover`; focus ring. Layout, left to right:
  1. Time column, fixed 64px: pickup time Heading 20/500, tabular numerals (`HH:MM`, the booking's Prague wall-clock time, no conversion).
  2. Main column (flex 1, `min-width: 0`):
     - Line 1: pickup address, Body 16/500 `--admin-text`, single line, ellipsis.
     - Line 2: `ArrowRight` 16px (`aria-hidden`, plus visually hidden "to ") then drop-off address, Body 16/400 `--admin-text-muted`, single line, ellipsis. When there is no drop-off (as-directed) the line reads "As directed".
     - Line 3 (meta), Label 12/400 `--admin-text-muted`, `·` separated, wraps to a second line if needed: `{passenger first name}` · `{plate or Pending}` · `{vehicle class label}`. The plate is `--admin-text`, weight 500, tabular numerals; "Pending" is muted weight 400 (no plate set on the driver). Class label comes from `formatVehicleLabel`.
  3. For rides already in progress only (booking status `en_route`, `on_location`, `on_board`): a `StatusBadge` ("En route", "On site", "On board") sits above line 1 on the right of the time column's row, so the active ride is obvious. Plain `assigned` rides show no badge.
- Accessible name of the row: "{time}, {pickup} to {drop-off}, passenger {first name}, plate {plate|pending}, {class}".
- **Empty:** icon `CalendarDays` 48px in a 96px circle `--admin-hover` (icon `--admin-text-muted`), centered, padding 48px 24px; heading Heading 20/500 "No upcoming rides"; body Body 16/400 muted "Rides you accept will appear here."; when the driver has live offers, a text link "Review {n} offer(s)" (`--admin-accent-text`, 48px hit area, "1 offer" / "{n} offers") to `/driver/offers`.

### Past

Terminal rides of this driver (booking `completed`, `cancelled` or `no_show`, assignment accepted), newest first, grouped by Prague date, one **Prague month** at a time.

- **Month bar:** margin `16px 24px 0`, three items: `ChevronLeft` link (48x48, neutral outline, `aria-label="Previous month"`), centered month label Heading 20/500 ("November 2026", `<h2>`), `ChevronRight` link (48x48, `aria-label="Next month"`). The next link is disabled (`aria-disabled`, 40% opacity via `--admin-text-muted` colour, not clickable) at the current Prague month; the previous link is disabled when no earlier month holds a past ride. Default month: the current Prague month.
- **Fee total** (`MonthTotalCard`), only when at least one **completed** ride in that month has `driver_price_czk` > 0: margin `16px 24px 0`, padding 16px, `--admin-surface`, 1px `--admin-border`, radius `--admin-radius-md`. Caption Label 12/500 muted "Your fees for completed rides"; value Display 28/500 tabular, the string returned by `formatCZK(sum)` (for example `12 400 Kč`). **When the sum has no priced ride the card is not rendered at all** (never "0 Kč", never "0 CZK"; D-11). Cancelled and no-show rides never add to the total.
- **Row:** same as Upcoming plus a `StatusBadge` at the right of the time column's row: `Completed` (completed, ok family), `Cancelled` (cancelled, danger), `No-show` (no_show, danger). No per-row fee.
- **Empty month:** same empty-state pattern, `CalendarDays`, heading "No past rides in {November 2026}", body "Use the arrows to see other months." (the body is omitted when no earlier month has rides).

### Loading and error

`loading.tsx` for each tab: the page title plus three static placeholder cards (`--admin-hover` blocks, 80px high, radius `--admin-radius-md`, no animation, `aria-busy="true"` on the region, `aria-label="Loading rides"`). `error.tsx`: `TriangleAlert` 48px in a 96px circle `--status-danger-bg` (icon `--status-danger-fg`), heading "Could not load this page", body "Check your connection and try again.", primary "Try again" (accent, 48px, calls `reset()`).

## Screen Contract: Offers (`/driver/offers`)

Page title "Offers". Subline (Label 12/400 muted, margin `0 24px 16px`): "Rides the office has offered to you. Only you can see them." Lists every live offer of this driver (pending, newest assignment of its booking, booking not terminal), earliest pickup first.

When push is supported, permission is `default`, no push subscription exists and the hint was not dismissed: an info banner (`--status-info-bg`, `--status-info-fg`, `Bell` 20px, radius `--admin-radius-md`, padding 16px, margin `0 24px 16px`). Text Body 16/400: "Turn on notifications to hear about new rides right away." The banner is never shown inside the push-enabled state or when the key is not configured.

### Offer card (`OfferCard`)

Margin `0 24px 16px`, padding 16px, `--admin-surface`, 1px `--admin-border`, radius `--admin-radius-md`, no shadow, vertical gap 16px.

1. **When row:** left column: day label Label 12/500 muted (`Today`, `Tomorrow`, `Fri 27 Nov`), under it the time Display 28/500 tabular (`14:30`). Right column (right-aligned), **only when the fee is a positive integer**: caption Label 12/400 muted "Your fee", value Heading 20/500 tabular from `formatCZK`. When the fee is empty the column is absent (no placeholder, no dash, no "0").
2. **Address timeline:** the trip-sheet timeline (87): two rows joined by a 1px `--admin-border-strong` line, pickup dot 12px filled `--admin-accent`, drop-off dot 12px ring with 2px `--admin-text` border; captions Label 12/500 muted "Pickup" / "Drop-off"; addresses Body 16/400, clamped to 2 lines (`driver-address-clamp`), `overflow-wrap: anywhere`. 3. **Meta line:** Label 12/400 muted: `Passenger {first name}` · `{vehicle class label}`. **First name only. No last name, phone, flight, notes, booking reference or client price** (D-12). The meta line wraps; the name is single-line with ellipsis inside its span.
4. **Actions:** stacked, gap 8px, full width, 48px: **Accept** (accent fill, `--admin-on-accent`, Body 16/500, radius `--admin-radius-md`) then **Decline** (neutral outline: 1px `--admin-border-strong`, transparent, `--admin-text`). Two new modes of `ConfirmStepDialog` (same sheet, scrim, focus trap, Escape and scrim behaviour as 87: bottom sheet on phones, centred from 600px, padding 24px, max-width 480px, gap 8px between stacked buttons).

|------|------------------------|--------------------|----------------|-----------------------------------|---------------|

One banner slot at the top of the list, single message at a time, Body 16/400, padding 8px 16px, radius `--admin-radius-md`, 20px leading icon, `role="status"` (ok, info) or `role="alert"` (danger, amber). Clears after 8s (ok and info) or on the next action.

## Accessibility Contract

- Every control is operable by keyboard; tab order follows visual order. Tab bar links are a `<nav>` with `aria-current="page"`. The Rides view switch is a nav of links, not ARIA tabs (the URL is the state).
- Icon-only controls carry `aria-label` (month arrows). The Offers badge is `aria-hidden`; the link name carries the count.
- Dialogs (accept, decline, disable) trap focus, label themselves, close on Escape, return focus to the invoking control; initial focus lands on the safe choice ("Not yet", "Keep offer", "Keep access").
- Switch: `role="switch"`, `aria-checked`, name from the label, state also stated in the helper text; the disabled-denied state explains why in text.
- Code field: single `<input>` with a visible label, `autocomplete="one-time-code"`, `inputmode="numeric"`; errors are `role="alert"` and focus returns to the field.
- Banners: `role="status"` (ok, info) or `role="alert"` (danger, amber); one visually hidden polite live region announces accepted and declined answers.
- `prefers-reduced-motion: reduce`: no spinner rotation (static `LoaderCircle`), no knob transition on the switch, no animation anywhere else (the cabinet has none beyond the spinner).
- Text sizing: no zoom lock; layout uses `dvh` and flex so 200% text zoom scrolls the page instead of clipping; the tab bar stays reachable (sticky) and the rows grow in height.
- Colour is never the only signal: statuses carry text, the active tab carries a top bar, the switch state is stated in text, errors carry text and `role="alert"`.
- Touch targets >= 48px; focus ring 2px `--admin-focus` with 2px offset on all hand-built controls (`data-driver-focus`).
