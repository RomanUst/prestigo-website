## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query (next, ended) -> sign-in page | attacker-controlled redirect target |
| browser -> request-code / verify | the form is the only UI caller; the server stays the authority |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-94-09 | Tampering | next parameter (open redirect) | medium | mitigate | safeDriverNext allow-list of /driver/rides, /driver/offers, /driver/you with the safeAdminNext hygiene; tested against //, backslash, .., control chars, absolute URLs |
| T-94-10 | Information disclosure | trip token carried in a sign-in URL | medium | mitigate | /driver/trip and /driver/response are rejected as next targets, so no token path reaches the login URL or its Referer |
| T-94-11 | Information disclosure | sign-in UI (account enumeration) | medium | mitigate | step 2 copy identical for every email; the form never reads the request-code body |
| T-94-12 | Elevation of privilege | a cabinet page that relies on a layout gate | high | mitigate | requireDriver() called by each page (enforced by the 94-14 source gate); the (cabinet) layout holds no auth logic |
| T-94-13 | Tampering | XSS via the email echoed on step 2 | low | mitigate | React text rendering only, no dangerouslySetInnerHTML |
| T-94-SC | Tampering | npm/pip/cargo installs | high | accept | Rationale: this plan installs no package |
</threat_model>
