# Phase 84 — UI Design Contract

> Visual and interaction contract for the Chatwoot Dashboard App panel (read-only booking history in the conversation sidebar). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Surface:** one iframe page, `app/embed/chatwoot-dashboard` (own root layout, no next-intl, no site chrome), rendered at 320-400 px wide inside the Chatwoot conversation sidebar. English only (D-07). Read-only: the only controls are Save token, Forget token, Refresh, Show more, Copy payment link, and plain links.

**Sources:** CONTEXT.md D-05..D-12 (locked layout, card fields, empty/hint states, Copy button), RESEARCH.md (handshake states, payment-state rule, theme via `appContext.theme`, status vocabulary, CSP `img-src 'self' data:` / `font-src 'self'`), `components/admin/StatusBadge.tsx` + `BookingsTable.tsx` (status vocabulary and hues), `app/globals.css` (brand tokens). Items marked *(default)* were not answered upstream and take the stated default.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between badge dot and label, gap between inline meta items, badge vertical padding |
| sm | 8px | Page gutter, gap between badges, gap between rows inside a card, badge horizontal padding, button inner padding |
| md | 16px | Gap between cards, gap between sections, token-entry form field gap |
| lg | 24px | Gap between header counters block and first section |
| xl | 32px | Top/bottom padding of full-panel states (empty, token entry, errors) |
| 2xl | 48px | not used |
| 3xl | 64px | not used |

Exceptions:
- 12px is allowed for card inner padding only (multiple of 4; 16px would leave about 256 px of text at a 320 px sidebar).
- Minimum interactive target height is 32px (mouse-driven desktop operator tool inside a dense sidebar; the 44px touch target does not apply). Minimum width 64px for text buttons.
- 2px focus ring offset and 1px borders are not spacing tokens.
- Layout must not scroll horizontally at any width from 280 to 400 px: every flex/grid child sets `min-width: 0`; long text uses `overflow-wrap: anywhere`.

## Typography

Exactly 4 sizes (12, 14, 16, 20) and 2 weights (400, 600).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 | 1.5 | Route, notes, empty/error text, field input, links |
| Meta | 12px | 400 | 1.4 | Booking reference, vehicle/pax/luggage line, flight, "searched for" line, helper text, "Updated hh:mm" |
| Label | 12px | 600 | 1.4 | Status and payment badges (uppercase, letter-spacing 0.04em), counter captions, button text, link text "Open in admin" |
| Heading | 16px | 600 | 1.25 | Section headings ("Upcoming", "Past"), card date/time line, state headings ("No bookings", "Connect your Chatwoot account") |
| Display | 20px | 600 | 1.2 | The two header counter values only (trips, total spent) |

Rules:
- Numbers (amounts, dates, counters) use `font-variant-numeric: tabular-nums`.
- No italics, no letter-spacing on body text, no text below 12px.
- Brand serif (Fraunces) is not used: this is an internal tool and the page loads no webfont.

## Color

Theme is set from `appContext.data.theme` (`'light' | 'dark'`) via `<html data-theme>`. Before the context arrives, follow `prefers-color-scheme` so a dark-mode operator does not see a white flash on each conversation switch (Chatwoot builds a new iframe per conversation). All pairs below meet WCAG AA (4.5:1 for text, 3:1 for borders/focus).

| Role | Dark | Light | Usage |
|------|------|-------|-------|
| Dominant (60%) | `#0F1D2C` | `#FBF9F4` | Page background |
| Secondary (30%) | `#17293B` | `#F1EBDD` | Booking cards, token form panel, state panels; 1px border `#2B4056` / `#D6CAB4` |
| Text primary | `#F3EEE3` | `#16202A` | Body, headings, counter values |
| Text muted | `#A9AEB0` | `#5E6B75` | Meta text, captions, helper text |
| Accent (10%) | `#BFA06A` fill / `#D4BB86` text | `#7A5A28` fill and text | See reserved list |
| Accent on-fill text | `#0F1D2C` | `#FFFFFF` | Label inside accent-filled buttons |
| Destructive | n/a | n/a | No destructive actions in this phase (read-only; Forget token only clears a local value and is undone by re-pasting, so it needs no confirmation). Red appears only as the `cancelled` / `no_show` status hue and inline error text (`#F87171` dark / `#991B1B` light) |

Accent reserved for (exhaustive):
1. Filled primary buttons: "Save token" and "Copy payment link".
2. Keyboard focus ring on every interactive element (2px, offset 2px).
3. The 4px leading border on the nearest upcoming booking card (first in the Upcoming list), to mark "next trip".

Not accent: counter values (Text primary). Links ("Open in admin", "Create booking in admin", "Open Lead in EspoCRM") use Text primary with an underline; their hover state may switch the underline colour to accent, which is the only other accent use.

### Status badge hues (theme-scoped; same keys and labels as `/admin`)

Badge = 6px dot + uppercase Label text, 1px border at 25% of the foreground, radius 2px (matches admin). Dark column values are the existing admin `variantStyles`; light column values are required so the badge is legible on a light sidebar.

| Key | Label | Dark bg / fg | Light bg / fg |
|-----|-------|--------------|---------------|
| unpaid | Unpaid | `#3a1a12` / `#f59e0b` | `#FEF3C7` / `#92400E` |
| pending | Pending | `#3a2a1a` / `#fb923c` | `#FFEDD5` / `#9A3412` |
| confirmed | Confirmed | `#1a2f3a` / `#38bdf8` | `#E0F2FE` / `#075985` |
| assigned | Assigned | `#1a3a35` / `#34d399` | `#D1FAE5` / `#065F46` |
| en_route | En Route | `#2a1f3a` / `#a78bfa` | `#EDE9FE` / `#5B21B6` |
| on_location | On Location | `#3a2a0a` / `#fbbf24` | `#FEF9C3` / `#854D0E` |
| completed | Completed | `#1a3a2a` / `#4ade80` | `#DCFCE7` / `#166534` |
| cancelled | Cancelled | `#2a1a1a` / `#f87171` | `#FEE2E2` / `#991B1B` |

Driver trip progress (Phase 67) reuses hues: `en_route` = En Route (violet), `arrived` = Arrived (amber, on_location hue), `on_board` = On Board (emerald, assigned hue), `completed` = Completed (green), `no_show` = No-Show (red, cancelled hue).

Payment badge (derived server-side, rule A1 in RESEARCH): `paid` = "Paid" (completed hue), `awaiting_payment` = "Awaiting payment" (unpaid hue), `quote` = "Quote" (confirmed hue). For `cancelled` bookings no payment badge is rendered. Unknown status keys fall back to the raw key in the muted neutral style (`secondary` bg, `muted` fg) so a new backend status never crashes the card.

Status is always conveyed by the text label, never by colour alone.

## Layout and Interaction Contract

### Page structure (top to bottom, single column)
1. **Header row:** panel title "Bookings" (Heading) left; "Refresh" text button right (Label, 32px high). Under it the contact line in Meta: the email or phone that was searched, plus the verification hint (below) and, when `phone_mismatch` is true, the Meta line "Phone matches a different customer" (muted, no colour).
2. **Counters:** two equal cells in a `dl`, each Display value over a Label caption: "Trips" and "Total spent". Total spent is formatted with `Intl.NumberFormat('en-IE', { style: 'currency', currency: 'EUR' })` from server data, never a typed literal or the `€` character in source (pre-commit guard).
3. **Upcoming** section: Heading + count in Meta ("Upcoming · 3"). ALL future bookings, nearest first (D-05).
4. **Past** section: Heading + count. 10 most recent, newest first; below them a full-width text button "Show {n} more" expands in place (no new request, RESEARCH Open Q3). If the server cap (200) is reached and there are still more, the last row is the link "Open all bookings in admin".
5. **Footer:** Meta line "Updated {hh:mm}" left, "Forget token" text button right (visible only when a token is stored).

Focal point: the counters and the accent-ruled next upcoming card are where the eye lands first; everything else is secondary.

Page gutter 8px. Cards are full-width blocks, 16px apart, 12px inner padding, row gap 8px.

### Booking card (D-06) — field order
1. Date/time (Heading, Europe/Prague, `en-GB`: "Thu 12 Nov 2026, 14:30"). If `pickup_utc` is null, show the wall-clock `pickup_date` + `pickup_time` and never drop the row. A "Return" label-badge (neutral style) follows the date on return legs.
2. Route in Body, wrapping: origin on the first line, then "to {destination}" on the second line (plain text, no arrow icon). Hourly bookings show "{origin} - {n} h".
3. Badge row: booking status badge, payment badge, then the reference in Meta (tabular, selectable).
4. Meta line: "{Vehicle class} · {n} pax · {n} bags · {amount}" using vehicle labels Business / First Class / Business Van (same map as admin).
5. Driver row (only if a driver is accepted): "{Driver name}" in Body plus the trip-progress badge if progress exists.
6. Flight (only if present): Meta "Flight {number}".
7. Notes (only if present): Body, muted label "Customer notes" in Meta above; clamp to 3 lines with a "Show full note" text toggle when it overflows.
8. Actions row: link "Open in admin" -> `/admin/bookings?search={booking_reference}` (new tab, `rel="noopener noreferrer"`); and, only for `awaiting_payment` with a valid https Stripe link, the "Copy payment link" button.

Optional rows are omitted entirely when empty (no "N/A" placeholders, no empty labels).

### Copy payment link (D-09)
- Visible only when payment state is `awaiting_payment` AND the link is `https:` on an allowlisted host (`buy.stripe.com`); anything else shows no button and no raw URL.
- Click: try `navigator.clipboard.writeText`; on failure `document.execCommand('copy')` on a hidden textarea; on failure reveal a read-only, auto-selected input holding the link with the Meta line "Press Ctrl/Cmd+C to copy".
- Success: button label becomes "Copied" for 2 seconds (still a button, `aria-live="polite"` announces "Payment link copied"), then reverts. The panel never opens or follows the payment link itself.

### Verification hint (RESEARCH Pitfall 9, recommended)
Meta line under the contact line, from `meta.hmac_verified` / `identifier` that the server returns as one boolean `verified`:
- verified: "Verified customer (signed in)"
- not verified: "Unverified email - confirm identity before sharing booking details" (Text primary, 600 weight, with the unpaid-hue dot so it is noticed). Never red.

### Refresh behaviour
Re-fetch on window focus, `visibilitychange` to visible, every 30 s while visible, and on the Refresh button. A re-fetch keeps the current content on screen (no skeleton); Refresh shows "Refreshing..." and is disabled meanwhile; the content swaps in when the response arrives. A 401 on any request clears the stored token and returns to the token-entry state.

### Interaction states (all interactive elements)
- Hover: underline for text buttons and links; filled buttons lighten 8% toward the page background; cursor pointer.
- Focus-visible: 2px accent ring, 2px offset; never removed. Tab order follows reading order.
- Disabled: 50% opacity, `cursor: not-allowed`, `aria-disabled`.
- Motion: only the loading skeleton pulse (1.2 s opacity 1 -> 0.6). Disabled entirely under `prefers-reduced-motion: reduce`.

### Accessibility
- One `h1` ("Bookings"); section headings are `h2`; each card is an `article` with the date/time as its `h3`.
- Counters are a `dl`. Badges are `span` with visible text. The list of cards is a plain `ul`.
- State changes (loading -> loaded, errors, "Copied") are announced through one `aria-live="polite"` region; errors use `role="alert"`.
- All text meets AA in both themes (pairs above).
